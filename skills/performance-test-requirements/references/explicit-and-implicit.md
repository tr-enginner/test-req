# 显式与隐含性能需求

## 显式需求

原文直接把可测时间指标作为要求，例如明确说明周期上限、频率下限、间隔范围、处理时长、响应时限或时间误差。仅说明固定调度周期或执行节拍不成立。

`related_description` 直接写性能类型，例如 `响应时间`。

## 隐含需求

原文未把该约束命名为性能要求，但上下文已经给出完整、可测试的时间阈值、范围、周期/频率边界或精度。不能把普通定时配置包装成隐含性能需求。

`related_description` 写为 `隐含需求：` 加性能类型，例如 `隐含需求：处理时间`。

不得从协议常识、行业经验或其他项目补造数值和单位。只有“及时”“快速”“实时”等定性词，或无法判断某时间参数是否构成验收边界时，将问题写入 `open_questions`，不生成row。明确属于固定调度或设计约束时按Skill规定的“已排除”格式记录审计说明，不伪装成待确认问题。
