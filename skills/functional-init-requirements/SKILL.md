# 初始化功能需求提取
## source_refs契约
每个`processing[]`项的`source_refs`必须是非空、去重数组，逐字复制document structure的`sections[].source_ref`，至少一个`primary::`；supporting只能补充。合法：`["primary::SRS-3.2.1", "supporting-002-protocol::SRS-8.4"]`。禁止裸章节ID、标题、路径、source plan信息和table_id。只引用直接支持当前TR的最具体章节；item顶层`source_refs`由finalize汇总，worker不得手工输出。

## 目标

生成功能标题树 `routing.initialization_title_no` 指向的初始化功能需求项下各叶子标题内容。每个初始化叶子也必须写输入流说明、处理、输出流说明和测试要求，并保留初始化说明表；不生成测试用例、通过准则、总 `test-requirements.json` 或完整第三方测试文档。

## 固定流程与参考

必须先读取并执行 [初始化对象识别与 TR 拆分](references/initialization-object-workflow.md)，严格按“识别对象 → 总结 summary → 每对象一个 TR → 选择模板 → 关联表格 → 生成输入输出流”的顺序工作。

- 识别到 BM3803FMGRH 时，必须读取 [BM3803FMGRH 初始化模板与输出示例](references/bm3803fmgrh-template.md)，按其中完整表格示例组织输出。
- 识别到 80C32 时，必须读取 [80C32 初始化模板与输出示例](references/80c32-template.md)，按其中完整表格示例组织输出。
- 识别到 CAN 总线时，必须读取 [CAN 初始化模式选择、模板与输出示例](references/can-initialization-template.md)，按所选模式的完整 A/B 表格示例组织输出。
- 其他初始化对象按来源证据组织 TR 和表格，不得套用无关模板。

## 来源使用

- 需求规格说明书用于确认项目确实存在某个初始化对象、初始化动作或初始化约束。
- 器件手册、芯片手册、协议手册可以补充寄存器地址、寄存器字段、合法取值、位含义、配置含义和计算依据。
- 手册信息必须能对应到需求文档中的初始化对象或初始化动作；不要仅凭手册凭空新增项目初始化需求。
- 所有初始化对象的地址、初值或必要含义无法从当前项目需求、匹配手册或所选模板确认时统一写 `XX`；不要留空、删除对象、复制不匹配模板的示例值或根据局部位语义补造具体值。
- 默认不使用代码。若任务 payload 显式允许代码，也只能作为后续实现核对信息，不替代需求依据。

## 标题挂载

- 处理 finalized 功能标题树中 `routing.initialization_title_no` 指向的初始化功能需求项下叶子标题。finalized 标题树始终包含初始化节点，即使源功能标题树没有初始化标题也不得跳过。
- 必须读取 `chapter2-system-overview.json` 中的处理器和运行环境、`hardware-interface-model.json` 中的全部真实硬件接口，并结合来源文档建立强制初始化清单，覆盖处理器、每个接口、片上定时器、已识别寄存器/端口和其他运行环境对象。
- 每个内容项必须沿用标题树叶子的 `title_no`、`title`、`tr_code`、`source_ref`。
- 不要生成 `TR-GN-INIT-001` 这类新编号。

## 内容结构


每个 item 固定包含：

- `summary`：用一个无换行、无编号、无项目符号的完整句子概括全部实际初始化动作和对象。
- `input_flow`：只写来源明确的主动触发方式；没有主动输入时必须写 `["无。"]`，不要把推测的上电或复位阶段当作输入。
- 不要输出 `processing_preamble` 字段；无法自然映射为“名称、地址、确定初值、初值含义”的流程参数、逻辑标志、运行状态、条件赋值、公式、字段映射、校验规则和前置说明写入最相关的 `processing.content`，可表格化的寄存器/地址配置只写入关联表格。
- `processing`：处理要求数组。每项包含 `requirement_id`、`source_refs`、`content` 和 `table_refs`；`source_refs` 非空且至少包含一个真实 `primary::` 引用；`requirement_id` 使用当前叶子的 `tr_code` 加 `-001`、`-002` 连续编号。
- `output_flow`：输出流说明数组，只写初始化后的状态、寄存器配置结果、端口状态、接口状态或可观测结果名称。没有输出时写 `["无。"]`。
- 不要输出 `test_requirements`；“测试要求”小节及其固定值由 DOCX 渲染器生成。
- `tables`：初始化说明表数组，每张表包含item内唯一的 `table_id`。

`processing.content` 使用一条或多条连贯的确定性自然需求语句，覆盖该 TR 承载的初始化动作。只有对象级动作时可写“软件初始化 BM3803。”；存在不适合表格化的流程参数、标志或状态时，必须逐项写清取值来源、状态变化或设置结果，例如“软件将固定指令序列流程参数恢复为来源规定的默认值，按上注内容初始化上注指令序列流程参数，并将初始化完成标志置为完成状态。”。禁止使用“应该”“应当”“应”“需要”“需”“可以”“建议”等措辞，禁止用“完成初始化配置”“初始化相关状态”代替明确行为。寄存器、地址、端口、位字段及确定初值只写入关联表格，正文不得重复表格已经完整承载的配置。

## 源初始化内容覆盖

- 读取 `routing.initialization_title_no` 对应的全部源章节及其子章节，先建立仅用于生成过程的初始化内容清单，逐项记录对象、参数、状态、标志、动作、触发条件和结果。
- 为清单中的每一项指定唯一主要承载位置：`processing.content` 或某张表的具体行；混合对象可以同时使用正文和表格，但同一配置不得重复描述。
- 固定指令序列参数、上注参数、加断电标志、初始化完成标志、总线节点状态、单板状态、条件赋值和运行初始状态必须纳入清单，不能因没有地址或寄存器而遗漏。
- 写出 raw JSON 前反向核对强制初始化清单：每一项都必须能在某个 TR 正文或初始化表格行中找到明确对应；缺少地址、初值或必要含义时用 `XX`，不得仅因缺值写入 `open_questions`。只有对象身份冲突或来源互相矛盾时才记录待确认问题。
- 不把 `summary`、`input_flow` 或 `output_flow` 视为 TR 覆盖证据；初始化内容必须落入 `processing.content` 或表格行。

## 动态测试用例友好处理描述

- `processing.content` 必须采用连贯的自然需求语句，不得拼接“触发时机：”“前置状态：”“初始化对象：”“设置动作：”“预期状态与可观测点：”等分类标签。
- `processing.content` 必须使用确定性陈述和可执行动词，例如“初始化”“复位”“设置”“清除”“读取并确认”，不得用“完成初始化配置”替代明确的对象级初始化动作。
- 优先写清“软件在什么条件下初始化哪个对象”。触发条件只有在来源明确且无法由表格承载时才补充；来源未明确时省略触发条件，直接写“软件初始化<对象>。”，不得推断通用的上电、复位或启动时机，也不要仅因缺少这些信息新增 `open_questions`。
- 逐项寄存器/地址/端口/位字段、初值和含义由关联表格承载。
- TR 关联表格时，`processing.content` 不得重复该表已经完整承载的寄存器名称、地址、初值、位值或字段含义；同一对象中无法表格化的流程、标志和状态仍必须保留在正文。最终 DOCX 的“具体初始化设置见表x。”由渲染器生成。
- 先按物理或逻辑设备确定初始化对象，再生成 processing。每个对象默认生成一个 TR；对象包含不同触发条件、独立结果，或合并后无法形成清晰可验证描述时，允许拆成多个连续编号 TR。寄存器、内部模块、端口和位字段不得据此反推新对象。
- CPU 型号是一个对象；其中断控制器、优先级控制、定时器、GPIO、存储控制器等内部模块不得拆成独立对象。例如 80C32 的 IE、IP、TMOD、TCON、PCON、TH1/TL1、TH0/TL0 必须按模板顺序归入同一个 CPU TR 和同一张表。
- CPU 内部定时器及其预分频器必须并入 CPU 初始化：定时器计数寄存器、重载寄存器、控制寄存器、预分频计数寄存器和预分频重载寄存器全部作为 CPU 初始化表中的行。禁止生成“定时器初始化”独立 TR，禁止生成“定时器初始化说明表”或“预分频器初始化说明表”独立表格。
- 即使需求把“定时器初始化”写成单独段落，只要定时器是 CPU 片上外设，也必须回收到对应 CPU 对象的 processing 和汇总表；只有来源明确表明它是 CPU 外部独立定时器芯片时，才可作为独立芯片对象。
- 独立芯片按芯片实例划分对象，其内部功能模块不得拆分 TR。每个命名数据缓冲区或全局变量分别作为一个数据对象。
- 如果某个字段含义在来源中未明确，不能补造具体内容；表格中的必要含义、地址或初值写 `XX`。触发条件未明确时直接省略；仅对象身份冲突或来源互相矛盾时写入 `open_questions`。
- `input_flow` 和 `output_flow` 保持名称短语；来源明确的设置细节和结果写入 `processing.content`。

## 来源表格解析与初始化表生成

- 必须识别初始化来源中的表格引用，包括“见表xx”、“见附录表xx”、“表x/表y格式”、“按表xx格式”、“按附录J”、“参见表”、“参考表”、“参考附录表”和同义写法。
- 遇到表格引用时，必须优先用 `grep` 搜索表号、附录名、寄存器名、接口名、字段名或相邻关键词；如果 `grep` 不能定位，必须用 `read` 读取相关来源文本并在已读内容中定位表格上下文。
- `processing.content` 禁止出现来源中的“见表xx”、“见附录表xx”、“按表xx格式”、“参考附录表格”、“见上述表格”，也禁止改写成“依据xxx章xx表：<表内容展开详细描述>”。
- 将上述要求作为生成质量自检执行；不要依赖代码正则在 raw 复用或 finalize 阶段拦截此类文字。
- 必须把来源表格语义展开到 `tables.rows`，包括寄存器/接口地址、端口、位字段、初值和初值含义；不得把这些内容复制到 `processing.content`。
- 找不到明确表格内容时不得编造，在 `open_questions` 写明缺失的表号/附录名和已搜索关键词。

## 表格规则

初始化说明表是模型生成的抽取汇总表，不要求来自源文档原表。

- 每张表必须有当前item内唯一的 `table_id`，并且只能被一个 `processing.table_refs` 引用。
- 一个processing可引用0到多张表；无可表格化承载对象的等待、顺序或状态动作使用 `table_refs: []`。
- 禁止未知引用、重复引用、多个TR共享同一表以及未被任何TR引用的孤立表。
- 除 CAN 多通道外，每个具有可表格化配置的初始化对象最多生成一张包含全部明细行的汇总表；整个对象不适合表格时不生成表。
- CAN 总线是一个初始化对象：同一 CAN 类型只生成一个 processing。单通道生成一张包含全部寄存器行的汇总表；CANA/CANB 分别生成一张多行汇总表，并由同一个 `table_refs` 关联。不得按 BTR、OCR、CDR、IER 等单个寄存器拆分 TR 或表格。
- 最终DOCX由渲染器生成“具体初始化设置见表x。”和确定性表号；不要把该导航文字写入 `processing.content`。

表格列固定为：

| 名称 | 地址/寄存器地址 | 初值 | 初值含义 |
| --- | --- | --- | --- |

行只收录可落到以下承载对象的初始化项：

- 寄存器，例如 `IE`、`IP`、`TCON`、`TMOD`、`BTR0`、`BTR1`、`OCR`、`CDR`。
- 寄存器组，例如 `TH0/TL0`。
- 存储映射地址或接口地址，例如 `4800H`、`4C00H`、`5800H`、`CAN 地址 0`。
- 端口或引脚，例如 `P1.2`、`P1.4`、`P1.6`。

以下内容不要作为独立表格行：

- CAN 网络结构、总线拓扑等背景结构。
- CAN 波特率、协议标准、物理层标准等纯技术指标。
- DA 换算公式等解释性公式。
- 没有寄存器、地址或端口承载的软件计数/状态。
- EEPROM/SRAM 地址空间等资源范围，除非需求明确要求初始化某个具体地址。
- 没有初始化寄存器、地址或端口的等待/延时步骤。
- 固定指令序列流程参数和上注指令序列流程参数。
- 加断电标志、初始化完成标志、总线节点状态和单板状态。
- 条件赋值、运行初始状态，以及没有自然地址和确定初值的软件逻辑状态。

以上内容必须改由 `processing.content` 明确描述，不能为满足四列表格格式而填写虚构地址，或在 `初值` 中写 `默认值`、`初始状态`、`完成`。

## 字段规则

- `名称`：寄存器优先使用“正式寄存器名称（寄存器代号）”格式，例如 `配置寄存器1（MCFG1）`、`总线定时寄存器0（BTR0）`。正式名称和代号必须来自需求、匹配手册或本 skill 的对应模板；只有代号而无法确认正式名称时保留原代号，不得猜测或翻译名称。
- 对 BM3803FMGRH、80C32 和 CAN 使用低自由度模板字段。模板内名称必须从对应 reference 逐字复制；名称中的中文、数字、大小写、空格、全角括号和英文缩写均不得翻译、缩写、扩写、概括或改写。
- BM3803FMGRH、80C32 和 CAN 所选模板中的每个名称行都必须按模板顺序保留。地址、初值或初值含义无法确认时将对应字段写 `XX`，不得删除、重命名或移动模板行。
- 项目来源明确要求但模板未列出的寄存器、端口或复位控制项可以追加在全部模板行之后；追加项优先逐字使用需求或匹配手册中的正式名称。能对应到模板已有行时必须填充该行，不得重复追加同义名称。
- 禁止用 `中断`、`I/O设备访问配置`、`PROM访问配置`、`CANA复位控制`、`模式控制寄存器`、`验收码0` 等概括或改写名称替代模板名称。
- 其他初始化对象的 `名称` 写完整寄存器、地址对象、接口对象或端口对象，不按单个位拆行。
- `地址/寄存器地址`：写来源明确的寄存器地址、接口地址、CAN 地址或端口名；无法确认时写 `XX`，不得写 `不适用`。
- `初值`：只写来源明确的数值、原码、物理量、电平序列或配置前后值。上下文明确给出配置前状态和配置后写入值时，优先使用 `配置前值→配置后值` 表示初始化过程，例如 `0→0330H` 表示 ITMP 从中断禁能状态配置为 `0330H`；统一使用字符 `→`，不加括号，不写 `->`。
- 只有配置前值和配置后值都能由需求、匹配手册的复位值及明确初始化步骤或来源表格确认时才使用箭头；只确认最终写入值时仍写单值，例如 `0330H`，不得推断配置前值。
- 每个表格行的 `初值` 只能填写一个确定值，或一个有充分证据的 `配置前值→配置后值`。禁止把命令值、状态码、可选配置、候选值或多个可能值用换行、空格、逗号、顿号、斜杠或“或”罗列在同一单元格中，例如不得写 `01H\n04H`、`40H/80H`、`00H、01H、02H`。
- 来源列出多个值及各自含义，但没有明确指出初始化实际写入哪一个值时，将 `初值` 写为 `XX`；不得从寄存器功能说明中选择、组合或臆造初始化值。相应候选值说明也不得伪装成已确定的 `初值含义`。
- `初值` 无法确认时写 `XX`。不要写 `使能`、`禁止`、`高优先级`、`低优先级` 这类语义词。
- `初值` 不得写 `默认值`、`初始状态`、`完成`、`上注值或默认值` 等泛化占位文本；这些内容不适合表格时应移入 TR 正文。
- `初值含义`：使用箭头值时分别解释箭头前后的状态及变化过程，例如 `0 表示中断禁能；写入 0330H 后使能定时器中断1、定时器中断2、IO0中断和IO1中断。`；单值则解释该值、相关字段、位含义或物理含义。

## 内容完整性

- `summary` 按动作归并对象：初始化对象写成“对 A、B、C 进行初始化”，复位对象接写“并复位 D、E”；其他来源明确的动作按同样方式归并。
- `summary` 必须覆盖运行环境和硬件接口产物中实际识别到的全部初始化对象，不写“识别到的初始化对象包括以下几类”、对象数量、CPU/总线接口/独立芯片/数据对象等分类标签。
- 某类对象不存在时直接省略，不得写“无独立芯片需要初始化”“未识别到独立芯片”或其他空类别占位说明。
- 执行条件仅在来源明确时作为 `summary` 句首保留；来源未说明上电、复位或启动条件时不得自行补充。
- 生成 `summary`、表格 `title`、`rows` 中各字段时，不得使用“等”“等等”“之类”“相关”等省略语来概括未列出的初始化对象、寄存器、地址、字段或位含义。
- 遇到多个初始化对象、寄存器、端口、位字段或取值含义时，必须逐项列出；例如不要写“IE、IP 等寄存器”，应写“IE 中断允许寄存器、IP 中断优先级寄存器”。
- 如果来源只给出概括性描述而无法展开完整清单，不能用“等”补齐；应只写已定位到的具体对象，并在 `open_questions` 中说明缺失的清单或待确认对象。
- 自查所有生成的中文说明字段，凡“等”表示省略时都必须删除并改为完整列举；固定术语本身包含“等”且不是省略含义时才可保留。

## 条目化表达

- 初始化内容应尽量条目化，但 `summary` 是唯一例外；不要把多个寄存器、端口、位字段或初值含义全部挤在一个长段落里。
- `summary` 必须是一个自然段中的单句，禁止换行，禁止使用 `1.`、`2.`、`a.`、项目符号或冒号引出分类清单。对象较多时仍按动作归并，用顿号、逗号和“并”连接。
- 表格必须一行对应一个明确承载对象；多个寄存器、地址、端口或引脚不要合并进同一行。能拆成 `IE`、`IP`、`TCON`、`TMOD` 等独立对象时，应分别成行。
- `初值含义` 中如果包含多个位字段或多个约束，应使用换行条目或分号分项，例如 `1. EA=1 表示允许总中断。\n2. EX0=1 表示允许外部中断 0。`，不要挤成一个无层次的长句。
- 条目化不得牺牲可追溯性：对象必须来自运行环境、硬件接口产物、源需求或可引用手册；对象已确认但初始化细节无法确认时保留条目并用 `XX` 占位。

## 模型生成 Word/DOCX 默认格式

当任务明确要求你直接生成或整理 Word/DOCX 内容时，使用以下默认格式；如果当前 workflow 只要求 raw JSON，则不要生成 DOCX，只把这些规则作为后续 Word 生成约束：

- 正文：中文宋体，小四；英文和数字 Times New Roman，小四。
- 一级标题：黑体，三号，加粗。
- 二级标题：黑体，小三，加粗。
- 三级标题：黑体，四号，加粗。
- 四级及以下标题：黑体，小四，加粗。
- 行距：单倍；正文段落尽量紧凑。
- 表格标题：置于表格上方并居中，例如“表 4-1 XXX表”。
- 表格宽度：页面宽度 100%。
- 表格边框：普通单线边框。
- 第一行作为表头：浅灰底、加粗。
- 表格正文：宋体，五号，白底。
- 单元格文字：左对齐、垂直居中，保留少量内边距。

## 自查

- 表格只有四列：`名称`、`地址/寄存器地址`、`初值`、`初值含义`。
- 没有 `来源`、`备注/疑点` 或 `分类` 列。
- 没有地址为 `不适用` 的行。
- 没有把网络结构、技术指标、公式、无地址计数状态作为独立表格行。
- 所有内容都挂在 `routing.initialization_title_no` 下真实叶子标题上，并沿用标题树 TR 编号。
- 每个 item 都包含 `input_flow`、`processing`、`output_flow` 和 `tables`；初始化没有输入时 `input_flow` 为 `["无。"]`。
- 已先识别 CPU、总线接口、独立芯片、数据缓冲区和全局变量，`summary` 覆盖全部对象，processing 按对象顺序一对象一 TR；同一 CAN 类型的多个通道只占一个 TR。
- `summary` 是无换行、无编号、无分类标签的单句，已按初始化、复位等动作归并实际对象；不存在的对象类别已完全省略。
- 已逐项核对“源初始化条目 → TR正文或表格行”，不存在只在 summary/input_flow/output_flow 中出现而未被 TR 覆盖的初始化内容。
- 已逐项核对“对象 → 默认一个 processing → 零或一张汇总表”；只有 CAN 多通道允许同一 processing 关联多张通道表，不适合表格的对象使用 `table_refs: []`。
- CPU 片上定时器、预分频器及其寄存器均已并入 CPU 初始化 TR 和 CPU 初始化汇总表，未生成独立定时器 TR 或表格。
- BM3803FMGRH/CAN 已读取对应 reference，并直接参照完整输出示例；未用示例地址或初值冒充项目事实。
- BM3803FMGRH/80C32/CAN 表已逐行核对所选模板的名称和顺序；模板名称全部逐字一致，未知地址、初值和含义已填写 `XX`，来源明确的额外项只追加在模板行之后。
- 表格中的寄存器名称已优先写成“正式寄存器名称（寄存器代号）”；未将 `MCFG1`、`BTR0` 这类已有正式名称依据的寄存器只写成裸代号。
- 已逐行检查配置前后状态；上下文同时支持两个值时，`初值` 使用 `配置前值→配置后值`，并在 `初值含义` 中解释状态变化；证据不足时未臆造箭头前值。
- 每个 `初值` 单元格只有一个确定值、一个有证据的迁移值或 `XX`；未罗列多个候选值，无法唯一确定时已填写 `XX`。
- `processing.requirement_id` 从当前 `tr_code-001` 开始连续递增。
- 不要输出 `test_requirements`；DOCX 渲染器会固定输出充分性 C1、C2、C3、C4，终止要求 Z1、Z2，优先级高优先级。
- `processing.content` 已使用一条或多条确定性自然需求语句覆盖对象级动作及所有不适合表格化的参数、标志和状态；来源明确时包含触发条件。
- 固定指令序列参数、上注参数、加断电标志、节点/单板状态和完成标志未被强行写入四列表格，`初值` 中未使用“默认值”“初始状态”“完成”等占位文本。
- `processing.content` 未使用“应该”“应当”“软件应”“需要”“可以”“建议”等非确定性措辞，未使用“完成初始化配置”代替明确的初始化动作。
- 不要输出 `processing_preamble`；源需求中的公式、非表格化字段映射、校验规则和前置说明必须合并进最相关的 `processing.content`，可表格化初始化设置写入关联表格。
- `processing.content` 不得遗留来源中的“见表xx”、“见附录表xx”、“按表xx格式”、“参考附录表格”，也不得写“依据xx表”后展开表格；所有来源表格内容都必须写入 `tables.rows`，或在 `open_questions` 说明缺失依据和已搜索关键词。
- 不得出现用“等”“等等”“之类”“相关”省略对象或字段的生成内容；应逐项展开，无法展开则写入 `open_questions`。
- 多个初始化动作、寄存器、端口、位字段或初值含义已经拆成条目、独立表格行或换行分项，没有全部挤在一个段落里。
