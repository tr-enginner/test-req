# 初始化对象识别与 TR 拆分

## 固定执行顺序

1. 读取 `chapter2-system-overview.json`、`hardware-interface-model.json` 和来源文档，识别强制初始化对象。
2. 按对象清单总结 `summary`。
3. 建立源初始化内容覆盖清单，为每项指定 TR 正文或表格行。
4. 每个对象默认生成一个 processing TR；不同触发条件、独立结果或不可清晰合并的行为允许拆分。
5. 仅为适合四列结构的寄存器/地址配置关联初始化表。
6. 生成输入流和输出流，并反向核对源清单没有遗漏。

## 对象识别范围与来源

按以下类别和顺序识别，同类对象按来源出现顺序排列：

1. CPU：从需求规格的系统概述、运行环境说明识别型号，再读取匹配的芯片手册章节。
2. 总线接口：从硬件接口和初始化章节识别 1553B、CAN、串口等通信核心。
3. 独立芯片：识别 AD、Flash 等外围功能芯片及其实例。
4. 数据对象：从初始化章节、功能模块默认值、状态位要求、数据缓冲区和全局变量定义识别。

即使需求规格没有初始化章节，也必须为运行环境与硬件接口产物中识别到的处理器、每个真实接口、CPU片上定时器、寄存器、端口及其他运行环境对象生成初始化内容。需求规格中的明确对象、动作和值优先；匹配模板可补全已识别对象的必要行，辅助芯片/协议手册只能补充已确认对象。`allow_code=false` 时不得读取代码或软件分析产物；`allow_code=true` 时才可用它们补充缓冲区和全局变量定义。

对象按物理或逻辑设备划分，不按内部模块、寄存器或配置动作划分：

- 一个 CPU 型号是一个对象；中断控制器、优先级控制、定时器、GPIO、存储控制器均属于该 CPU。
- CPU 片上定时器和预分频器不是独立初始化对象。其计数、重载、控制及预分频寄存器全部进入 CPU 初始化 TR 所关联的同一张 CPU 初始化汇总表。需求章节是否单独描述定时器，不改变对象归属。
- 一个总线类型是一个对象；CANA/CANB 是同一 CAN 对象的通道，不是两个 TR。
- 独立芯片按芯片实例划分；芯片内部模块仍属于同一对象。
- 每个命名数据缓冲区或全局变量分别作为一个数据对象。

## Summary 与 TR

- `summary` 必须用一个无换行、无编号、无项目符号的完整句子概括本 item 内实际存在的初始化动作和对象，不遗漏、不增加。
- 按动作归并对象：使用“对 A、B、C 进行初始化，并复位 D、E”组织同类动作；其他明确动作采用相同方式归并。
- 不输出识别过程、对象数量或 CPU、总线接口、独立芯片、数据对象等分类标签。某类对象不存在时完全省略，不写“无独立芯片需要初始化”或“未识别到独立芯片”。
- 只有来源明确说明执行条件时才把条件放在句首；不得凭常识补写上电、复位或启动条件。
- 每个对象默认生成一个 TR，按对象顺序从当前 `tr_code-001` 连续编号；对象包含不同触发条件、独立结果，或合并后无法清晰验证时允许拆为多个连续编号 TR。
- 同一 CAN 类型下的 CANA、CANB 等通道视为一个对象：只生成一个 TR，可通过 `table_refs` 关联多张通道表。
- 每个 TR 使用一条或多条确定性自然需求语句覆盖初始化内容。来源明确触发条件时写“软件上电或复位后初始化 BM3803。”；无法自然进入四列表格的流程参数、标志和状态必须在正文逐项写清取值来源、状态变化或设置结果。禁止使用“应该”“应当”“应”“需要”“可以”“建议”，也禁止用“完成初始化配置”代替明确行为。
- 只有能自然映射为“名称、地址、确定初值、初值含义”的寄存器、端口、引脚或地址配置才生成表格。整个对象不适合表格时使用 `table_refs: []`。
- 除 CAN 多通道外，每个具有可表格化配置的对象最多生成一张多行汇总表。CAN 单通道生成一张表；CANA/CANB 分别生成一张多行表，由同一个 TR 引用。

## 表格适用性与覆盖

- 固定指令序列参数、上注参数、加断电标志、初始化完成标志、总线节点状态、单板状态、条件赋值和运行初始状态由 TR 正文描述。
- 混合对象可由正文描述流程/状态，同时关联寄存器配置表；正文不重复表格已经完整承载的配置。
- 禁止在 `初值` 中使用“默认值”“初始状态”“完成”“上注值或默认值”等泛化文本，也不得为满足表格格式虚构地址；地址、初值或必要含义缺失时统一写 `XX`。
- 生成前逐项提取初始化章节中的对象、参数、状态、标志、动作、触发条件和结果；生成后确保每项都能在 TR 正文或表格行中找到。
- `summary`、`input_flow` 和 `output_flow` 不作为 TR 覆盖证据。已识别对象不得因初始化细节缺失而省略，缺少地址、初值或必要含义时写 `XX`；不得仅因缺值记录 `open_questions`，只有对象身份冲突或来源互相矛盾时才记录。

## 正反例

正确的 summary：

> 软件上电或复位后，对 BM3803FMGRH、一级 CAN 总线、遥测参数和固定指令序列流程进行初始化，并复位一级 CAN 总线、SpaceWire 总线、二级 CAN 总线和 SPI 总线。

上例中的“软件上电或复位后”只能在来源明确支持时使用。实际项目不存在独立芯片初始化时，句中不出现“独立芯片”，也不补写任何“无独立芯片”说明。

错误的 summary：

> 识别到的初始化对象包括以下 4 类：
>
> 1. CPU：BM3803FMGRH。
> 2. 总线接口：一级 CAN 总线、SpaceWire 总线。
> 3. 独立芯片：无独立芯片需要初始化。
> 4. 数据对象：遥测参数、固定指令序列流程。

禁止上述编号、换行、分类标签、对象数量和空类别占位写法。

正确的 80C32 结构：

- 一个 `TR-GN-80C32Init-001`，正文用一句话概括 80C32 初始化。
- 一个 `table_refs: ["80c32-init"]`。
- `80c32-init` 表严格按 reference 依次写 IE、IP、TMOD、TCON、PCON、TH1/TL1、TH0/TL0 七组配置行。

禁止把同一个 80C32 拆成“中断配置 TR”“优先级配置 TR”“定时器配置 TR”“外部中断触发 TR”，也禁止为 IE、IP、TMOD、TCON 分别生成单行表。

正确的 BM3803FMGRH 结构：

- 一个 BM3803FMGRH CPU 初始化 TR，关联一张 BM3803FMGRH 初始化汇总表。
- 强制中断、配置、I/O、中断清除、缓存控制、定时器1、定时器2、预分频器和存储器容错寄存器均作为该表中的行。
- 禁止另建“定时器初始化 TR”和“定时器初始化说明表”。只有来源明确说明使用 CPU 外部独立定时器芯片时，才按独立芯片处理。

正确的 CAN 结构：

- 单通道 CAN：一个 TR 关联一张包含 BTR0、BTR1、OCR、CDR、IER 等寄存器行的表。
- CANA/CANB：一个 TR 关联 CANA、CANB 两张多行通道表。

写出 raw JSON 前，检查 `源初始化条目 → TR正文或表格行`，并逐对象检查 `对象 → 默认一个 processing → 零或一张汇总表`；只有 CAN 多通道允许一个 processing 关联多张表。

## 输入流与输出流

- 只有来源明确存在主动触发时才写入 `input_flow`，并保留具体触发方式，例如“系统上电复位”“软件复位”或明确的复位指令。
- 上电或复位若只是软件执行阶段而不是外部主动输入，不得凭常识补入。
- 无主动输入时固定写 `["无。"]`。
- `output_flow` 只写来源支持的初始化完成状态，例如寄存器配置状态、总线就绪状态、芯片状态、缓冲区初始状态或全局变量初始状态。
- 不得为了填充输出流而虚构就绪标志或可观测点；没有明确输出时写 `["无。"]`。
