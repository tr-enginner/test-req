# CAN总线接口领域补充

同时使用 `$hardware-interface-modeling` 和 `$hardware-interface-dataflow-constraints`。本 Skill 只补充 CAN 领域经验；发生冲突时，以这两个通用 Skill 为准。

## 检索线索

- 检索 CAN、CANA、CANB、CAN 总线、总线控制器、收发器、通信对象、波特率、传输速率、工作模式、时钟频率、技术规范、帧格式、数据格式、基地址、冗余和中断挂接。
- 当前候选若已由发现阶段把同一父章节下仅以 A/B 通道标识区分的 CANA/CANB 合并，必须同时读取两个来源章节；不得再拆成两个三级接口。一级 CAN、二级 CAN、不同父章节、不同通信对象或有独立物理接口证据的候选仍分别建模。
- 仅从当前候选及其来源章节扩展检索，不因其他接口章节出现 CAN 词汇而扩大候选边界。

## Overview 内容组织

- CAN `overview`（测试需求界面中的 summary）必须明确通信对象、控制芯片、工作模式、波特率或数据传输速率、技术规范和数据格式。来源文档缺失某项必备要素时使用 `XX` 占位，不得省略，也不得根据协议常识、芯片资料或其他项目猜测具体值。
- 项目有证据时一并保留总线数量、时钟频率、接口或寄存器基地址、A/B 冗余关系，以及中断名称或挂接关系。中断信息无证据时不得用 `XX` 补造。
- 合并的 A/B 候选有互备证据时写“A、B两条总线互相备份，A总线基地址为XXX，B总线基地址为XXX”；关系不明确时写“A、B两条总线关系为XX”。A、B 基地址缺失时分别写 `XX`，不得因只找到一条通道的地址而省略另一条，也不得仅凭 CANA/CANB 名称推断互备关系。
- 中断窄范围例外只允许中断名称或挂接关系进入 `overview`；中断优先级、触发方式、ISR、中断使能和寄存器配置仍不得进入。
- 数据格式在 `overview` 中只作简洁概述，例如标准帧/扩展帧、标识符或整体帧结构；详细业务字段和原始格式表仍按方向放入对应 `input_tables` 或 `output_tables`，不得复制到 `overview`。
- 删除协议原理背景、重复通信方式、初始化时机、初始化动作、BTR/OCR/CDR 等寄存器初值和其他冗余描述。

### Summary 参考模板

- CAN `overview` 应参考下述模板的内容结构和详细程度。
- 项目中的实际参数必须来自当前候选及其来源文档。下述模板中的星务主机、SJA1000、Pelican、时钟、速率、地址和中断只用于示范组织方式，不得作为所有项目的固定事实。

```
软件通过CAN总线与星务主机进行通讯。CAN总线通讯控制由总线控制器SJA1000进行控制，工作模式为Pelican模式，时钟频率为11.0592MHz，数据传输速率为307.2Kbps。A、B两条总线互相备份，A总线基地址为0x2000，B总线基地址为0x4000，中断分别挂接在外部中断0和外部中断1上。
```

## 数据流与表格

- 始终以被测 CPU 软件为主体判定输入输出，允许只有输入或只有输出。
- CAN 数据流固定写成“输入流：<数据内容短名>。<数据内容说明>”或“输出流：<数据内容短名>。<数据内容说明>”。短名和说明只聚焦实际指令、数据、状态、请求或应答内容，不重复“通过 CAN 总线”“经 CAN 接口”“与某对象通讯”等已由 `overview` 说明的通信方式。
- 同一业务事务在 A、B 通道下内容等价时只生成一个 `topic`，必要时说明同时适用于 A/B 两通道；只有通道专属且内容不同的事务才分别保留，禁止按通道复制相同业务数据流。
- 接口级基地址、寄存器地址和静态通道映射表进入 `overview_tables`；初始化设置表和中断配置表不得进入。
- 接收帧和外部指令格式表进入对应 `input_tables`；软件发送帧、请求、应答或遥测数据格式表进入对应 `output_tables`。
- 同一 `table_id` 只能出现一次；不得新造、截断、删改、重画或摘要化原表。

## 通用契约边界

- 使用统一 `interface_id`、三级标题、可选 `topics[]` 及通用输入输出字段。
- `topics[]` 禁止 `content`，所有说明性正文统一进入 `overview`。
- 不新增字段，不恢复 CAN 专属 block、frame_format 或类型专属 DOCX 布局。
- 不得覆盖通用 Skill 的接口成立条件、来源边界、CPU 方向和跨接口隔离规则。
