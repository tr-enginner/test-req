# AD采集接口领域补充

同时使用 `$hardware-interface-modeling` 和 `$hardware-interface-dataflow-constraints`。本 Skill 只补充 AD 领域经验；发生冲突时，以这两个通用 Skill 为准。

## 检索线索

- 检索 AD采集、A/D采集、模数采集、采样通道、转换启动、转换完成、片选、通道选通、高位/低位数据地址、补偿、滤波和平均处理。
- 整理有证据的芯片名称、采集位数或分辨率、量程、转换时间、片选地址、通道选通地址、启动地址或标志、数据采集地址。
- 仅从当前候选及其来源章节扩展检索，不因其他接口章节出现 AD 词汇而扩大候选边界。

## 内容组织

- 将采集步骤、编码方式、数据组合方式、补偿、滤波和平均算法等非数据流说明写入三级节点 `overview`，不得生成 `topics[].content`。
- 有证据时按动作顺序简洁说明：选择通道、等待稳定、启动转换、等待完成、读取高低位、组合采集值、滤波或补偿。不得补造缺失步骤。
- 同一 AD 接口同时包含电压遥测量采集和电流遥测量采集时，将二者视为同一模拟量采集过程的两个处理分支：不同位宽、通道范围、采样次数、滤波和计算方法必须完整合并写入同一个三级 `overview`，不得分别生成“电压遥测量采集”和“电流遥测量采集”四级 `topics[]`。
- 合并电压与电流采集后，接口顶层 `input_flow` 统一概括实际存在的电压、电流模拟量输入，不得为两类采集重复生成同义数据流。
- 除上述电压/电流合并规则外，只有源文档存在其他独立采集主题或通信事务时才生成 `topics[]`；不得强制 AD 完全没有四级标题，也不得为通用采集流程虚构四级标题。

### Summary 参考模板

- AD 采集 `overview`（测试需求界面中的 summary）应参考下述模板的内容结构和详细程度。
- summary 必须包含芯片型号、位宽、转换时间、通道地址或数据地址等关键要素。来源文档缺失某项关键要素时使用 `XX` 占位，不得直接省略，也不得根据常识、芯片资料或其他项目猜测具体值。
- 项目中的实际参数和采集流程必须来自当前候选及其来源文档。下述模板中的 AD574A、地址、端口、量程和处理算法只用于示范组织方式，不得作为所有项目的固定事实。

```
模拟量采集由12位的AD574A芯片实现。AD574A量程为0～10V，数据转换时间最大为35μs，AD574A基地址为0xC000，高位地址为0xC002（8位有效），低位地址为0xC003（高4位有效）。转换完成信号端口是P1.0～P1.3（具体见表XX），每次采集前先启动AD转换（0xC000写入0x00）。
每一路模拟量采集过程为：
a. 先向模拟开关的片选地址0xC000写入00H，启动AD转换；
b. 若是电流遥测量采集，则取地址C002H中的高8位、C003H地址的高4位为本次采集值；连续采集5次，去掉最大、最小值，取余下数的平均值作为最终采集值，读取3次最终采集值取平均值作为最终的电流值进行遥测下传。
c. 若是电压遥测量采集，则当地址C003H的最高位为1B，则将本次采集数据设为最大值0xff舍弃；若地址C002H中采集数据最高位为1B，则将本次采集数据设为：地址C003H中采集数据左移1位，最低位置1B；若地址C002H中采集数据最高位为0B，则将本次采集数据设为：地址C003H中采集数据左移1位，最低位置0B；连续采集5次，去掉最大、最小值，取余下数的平均值作为最终电压遥测量采集值
```

## 数据流与表格

- 始终以被测 CPU 软件为主体判定方向，允许只有输入或只有输出。
- 接口级片选地址、通道地址、启动地址、数据地址、寄存器地址和静态通道映射表进入 `overview_tables`。
- 外部模拟量、采样数据或采集结果进入软件时，其事务数据表进入对应 `input_tables`；软件经接口发送启动、选通或控制信息时，其事务表进入对应 `output_tables`。
- 表格继续按来源原表处理，不关注或强制特定列名和列结构。同一 `table_id` 只能出现一次；不得新造、转换、截断、删改、重画或摘要化原表。

## 通用契约边界

- 使用独立 `interface_id`、统一三级标题、可选 `topics[]`和通用输入输出字段。
- 不新增字段，不恢复 AD 专属 block 或 acquisition_processes，不引入类型专属 DOCX 布局。
- `topics[]`禁止 `content`；说明性内容统一进入 `overview`。
