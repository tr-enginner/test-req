# 1553B总线接口领域补充

同时使用 `$hardware-interface-modeling` 和 `$hardware-interface-dataflow-constraints`。本 Skill 只补充 1553B 领域经验；发生冲突时，以这两个通用 Skill 为准。

## 检索线索

- 检索 1553B、MIL-STD-1553B、文档明确标注为其等效实现的 GJB 289A、BC、RT、BM、总线控制器、远程终端、总线监视器、RT地址、T/R、子地址、方式代码、字计数、双冗余总线、收发缓冲区、循环缓存、中断和零等待模式。
- 逐项检查并整理有证据的1553B总线芯片名称、接口符合的标准、总线传输速率、时钟频率、芯片寄存器基地址、芯片RAM基地址、是否采用零等待模式及其位数、挂接的中断、BC/RT/BM总线角色和RT地址。每项只在源文档明确给出时输出；JR65170、1 Mbps、16 MHz、外部中断2、RT地址21或任何具体地址等示例值均不得作为默认事实。
- 仅从当前候选及其来源章节扩展检索；单独出现“1553”、GJB 289A或通用总线术语，且没有明确的1553B接口关系时，不得据此扩大候选边界。

## 内容组织

- 将总线数量与冗余关系、通信对象，以及芯片名称、标准、速率、时钟、寄存器基地址、RAM基地址、零等待模式及位数、允许的中断挂接关系、总线角色和RT地址等有证据的非事务事实写入三级节点 `overview`。不得因个别属性缺失而省略其他已有证据的属性。
- 子地址分配、T/R、字计数或方式代码、周期和缓存方式用于理解接口静态映射与事务边界；参数注入、遥测、指令、状态和正确/错误应答等独立事务优先分别组织为 `topics[]`。
- 一个请求、返回和应答属于同一通信事务时放在同一四级主题，不按方向拆成两个主题。原文没有独立事务主题时允许使用接口顶层输入输出。
- `topics[]`禁止 `content`；所有说明性正文统一进入 `overview`。

## 方向判定

- 始终以被测CPU软件为主体。外部BC或其他终端经当前1553B接口送入软件的命令、参数注入和总线接收数据属于输入；软件经接口发出的遥测、状态、应答和其他数据属于输出。
- 软件被源文档明确标识为RT时，子地址分配表的 `T/R=0` 固定表示该RT接收，即被测软件输入；`T/R=1` 固定表示该RT发送，即被测软件输出。应用这条规则时仍须确认T/R列描述的是当前RT而非其他终端。
- 软件不是RT、终端身份不明确、T/R列主体不明确或T/R与直接数据交互证据冲突时，不得机械套用T/R；改用被测CPU软件边界判定。仍无法消除冲突时停止该表的方向归类并报告证据疑点，不得猜测。
- 协议层数据包自身的源/目的、请求/应答或上下行称谓不能覆盖CPU边界方向；不得把包内方向与1553B子地址方向混为一谈。

## 数据流与表格

- 总线数据及其子地址分配表、RT子地址分配表，以及方向、字计数或方式代码、周期、循环缓存和静态缓冲区映射等接口级静态表完整进入 `overview_tables`。原表中的T/R、子地址、内容、字计数/方式代码、周期、缓存方式和备注等列必须全部保留，不得按数据流拆表或删列。
- 命令、参数注入、外部发送给软件的数据包及其字节/位域格式表进入对应 `input_tables`；遥测、状态、应答和软件发出数据的格式表进入对应 `output_tables`。
- 每条输入流或输出流先写短主题名称，再用一两句说明软件通过真实接收/发送子地址对该数据执行的接收、解析、处理或发送动作，最后在存在对应原表时自然引出数据格式表。推荐句式为“输入流：<名称>。软件通过接收子地址<真实子地址>……，其格式如下表所示。”或“输出流：<名称>。软件通过发送子地址<真实子地址>……，具体格式如下表所示。”；不得把占位文本或示例子地址写入结果。
- 数据包、字节/位域、校验、ACK和序列控制等原表必须保持完整并唯一归类；同一 `table_id` 只能出现一次，不得新造、截断、删改、重画或摘要化原表。
- 1553B候选允许将源文档明确给出的中断号或名称及其挂接关系写入 `overview`，例如“挂接在外部中断2”；仅限识别接口连接所需的挂接事实。中断优先级、触发方式、ISR、中断使能和寄存器配置仍不得进入 `overview`，以初始化或中断配置为主要用途的表仍不得进入 `overview_tables`。

## 通用契约边界

- 使用统一 `interface_id`、三级标题、可选 `topics[]`及通用输入输出字段；1553B接口标识优先使用 `IF-1553B-001`，同类实例用末尾三位序号区分。
- 不新增字段，不引入1553B专属block、子地址schema或类型专属 DOCX 布局。
- 不得用协议标准常识补齐源文档未说明的速率、字长、命令格式、状态位、校验、响应时间、冗余方式或其他参数。
- 不得覆盖通用Skill的接口成立条件、来源边界、CPU方向、跨接口隔离和表格唯一归类规则。

## 输出前自查

1. 是否逐项检索芯片名称、标准、速率、时钟、两个基地址、零等待模式及位数、中断挂接、总线角色和RT地址，并且只输出有证据的事实。
2. 软件明确作为RT时，子地址表是否按 `T/R=0` 输入、`T/R=1` 输出解释；其他场景是否回到CPU边界且未猜测冲突方向。
3. 子地址分配原表是否完整进入 `overview_tables`，格式表是否唯一进入对应 `input_tables` 或 `output_tables`。
4. 每条数据流是否依次包含短名称、带真实接收/发送子地址的软件处理过程，以及存在原表时的格式表引导语。
5. `overview`是否只保留允许的中断号或名称及挂接关系，且排除了优先级、触发方式、ISR、中断使能和寄存器配置。
