# 质量检查

每个row写入前确认：

- 数据对象明确；
- 处理动作明确；
- 输入来源或处理依据来自原文；
- 可验证的处理结果明确；
- 主要验证对象是数据内容质量或通用表示预处理，且能脱离具体业务功能独立验证；
- 已按4.3接口协议→4.6边界→4.1核心功能→4.7数据处理的顺序完成排他裁决；
- 未把帧ID/长度/校验和失败及丢弃误写为数据剔除，也未把组帧/解帧/包头处理误写为数据转换；
- 未把文件位置选择、缓冲区寻址、烧录地址计算或写入控制误写为数据转换；
- 未仅凭“校验、计算、存储、输出、重组”等动词强行生成row；
- 遥测采集明确给出了采集来源、主动采集动作和可验证采集结果；
- 未把接口广播/报文/应答接收、协议解析、字段提取、暂存或定时读取误写为数据采集；
- 未把坐标、姿态、指向、角度修正、相位、控制码、轨道、导航或控制算法误写为数据转换或融合；
- 数据转换只包含单位、量纲、基础编码、数值格式和标准化等独立通用预处理；
- 未把数值范围、上下限和端点合法性误写为数据剔除；
- 未把定位标志、状态字、帧字段或协议合法性误写为数据剔除；
- 未把SRAM、文件、缓存或内部变量的业务暂存和读取误写为数据采集；
- `related_description`严格为五类之一；
- 需求描述可直接放入表4.7-1；
- 未把接口、性能、边界、功能、安全可靠性等其他章节内容改写为数据处理需求；
- 未补造原文没有的数据源、算法、阈值、单位、存储对象、输出结果或异常处理行为；
- row只有业务描述、`source_refs`和相关说明三个字段，不包含`requirement_id`；
- 普通不成立候选项已忽略，而不是写入否定性需求；
- 普通排除项没有写入`open_questions`；`open_questions`只记录引用缺失、决定分类的关键原文缺失、处理依据缺失或原文冲突，并且每项是字符串。
