# 分类规则

`related_description`必须选择以下五类之一：

- `数据采集`：软件主动从传感器、采集通道或明确外部数据源获取数据，并验证来源、内容或采集结果。接收广播/报文/应答归4.3；从SRAM、文件、缓存或内部变量读取业务输入，以及接收后暂存、定时读取和调度组帧归4.1。
- `数据转换`：单位、量纲、基础编码、数值格式和标准化等可脱离业务功能独立验证的通用预处理。坐标系、姿态矩阵、角度修正、指向、相位、控制码及其他任务核心算法归4.1；协议解析、字段提取、组帧/解帧和包头处理归4.3。不得使用“业务表示转换”作为成立理由。
- `数据剔除`：业务处理前对重复、过期、异常测量样本等进行质量清洗。数值范围、上下限和端点合法性归4.6；状态字、定位标志、帧字段及协议合法性归4.3；超界触发业务状态或控制动作归4.1或4.6。
- `数据融合`：多个独立数据源形成综合测量结果。任务核心姿态、轨道、导航或控制算法不得以融合名义进入4.7。
- `数据解释`：从已有数据结果得到通用质量状态、告警或派生信息。核心任务判决和控制状态机归4.1。

同一候选同时命中多类时，先按4.3接口协议→4.6边界→4.1核心功能排除，只有均不成立时才选择4.7类别。分类依据是主要验证对象，不是动作关键词。

以下不是数据处理分类：CAN帧合法性和非法帧丢弃；按特征码或序号选择文件位置；增加协议标识后重组并发送；按包计数计算烧录地址并写缓冲区。“校验、计算、存储、输出、重组”只是候选线索，不是成立条件。

同样排除：时间广播同步、状态维护和周期组帧；GNSS/姿态广播接收、解析和暂存；坐标变换、姿态矩阵、天线指向角、限位修正、通道相位和遥控码计算；经纬高或位置速度范围判断；定位标志和状态字合法性；接收上注包后保存SRAM并定时读取。
