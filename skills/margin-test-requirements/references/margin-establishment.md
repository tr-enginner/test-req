# 余量成立条件

余量需求必须同时具备：

1. 明确的资源、任务或通道对象；
2. 可追溯的能力上限、预算或总容量；
3. 可追溯的最大使用量、允许比例、峰值需求、负载阈值或剩余量约束；
4. 能力与需求属于同一对象且单位/口径可比较。

只有总容量、地址、处理时间、周期、带宽或数据量而没有余量关系时不生成row。若同一对象的两部分证据位于相邻表格或条目，可关联后保留原文数值；不得跨对象拼接，不得自行计算原文未给出的容量、剩余量或百分比。存储证据有审计价值但缺少余量约束时写入`open_questions`；普通时间性能指标直接排除，不记录缺口。

附加门槛：

- 存储余量按独立存储区成立。同一介质的不同命名区或独立地址范围也分别计数；地址只识别对象，不用端点差值计算容量。
- `RAM区、PROM区、Flash-A区、Flash-B区；所有存储区余量均≥20%`应生成四行，并分别保留各区名称/地址及统一20%约束。若只有这些地址而没有统一或单区余量要求，则不生成row，不得补写20%。
- 20%只是常见原文阈值，不是模型默认值；原文给出25%等其他比例时保持原值。
- 时间余量必须出现原文明示的余量、预留比例或预算占用上限。`周期500μs、处理50μs`不得推导10%，`周期1ms、处理50μs`不得推导5%；这些只属于性能信息，不生成余量row，也不写open_questions。
- 吞吐余量除上述四项外，还必须具有可施加的峰值业务负载及可观察统计口径。缺少这类可测证据时不生成row，并在`open_questions`准确记录缺口。
