# 接口、功能、性能与安全性/可靠性需求分类

## 分类顺序

在合并候选项前，先判断主要测试对象：

- `interface`：跨接口传递的数据、信号或事务契约，包括格式、方向、请求—应答交互、单向发送，以及无效帧或字段对应的错误应答、不应答或丢弃。
- `functional`：有效数据被接受后执行的计算、业务判断、控制逻辑、内部状态管理、数据处理、存储或未定义明确输出契约的转发。
- `performance`：周期、响应/转换时间、帧间隔、延迟、抖动、吞吐率、传输速率、带宽或单位时间处理数量等定量指标。
- `safety_reliability`：通信硬件或链路的故障检测、隔离、降级、控制器复位/重新初始化、冗余重构、故障持续后的自动恢复，以及为维持安全状态或持续服务执行的系统级处置。
- `mixed`：同一原文同时包含接口契约与功能、性能或安全性/可靠性行为。

`functional`、`performance` 和 `safety_reliability` 不写入4.3的 `rows`，也不分配 `AUTO_TR_JK`。接口名称、接口标识或CAN/SPI/SpaceWire等总线名称的出现，本身不能证明该要求属于接口测试。

## 功能需求边界

以下主要验证软件业务功能，不属于4.3：

- 有效数据接收后的计算、处理、存储、内部状态更新或控制算法；
- “正确处理数据”“完成存储”“执行相应功能”等没有新增接口契约的结果；
- 未明确输出接口、接收方、消息格式或信号定义的笼统“转发”；
- 已由合法ID/非法ID、格式校验或请求—应答需求覆盖的识别动作。

只有当接收后的动作形成新的跨接口输出契约，即输出接口、接收方、消息/信号及格式或取值规则明确时，才把输入和输出组合为接口事务。无效输入不得触发正常业务动作可以作为接口异常结果，但不测试正常业务功能是否正确。

判断标准：接口测试验证“数据是否按契约跨过边界”；功能测试验证“数据进入软件后做了什么业务处理”。

## 安全性/可靠性边界

以下主要验证系统故障管理能力，不属于4.3：

- 总线进入 bus-off、控制器错误状态或硬件状态寄存器异常后的处置；
- 对接口控制器、收发器或总线进行复位、重新初始化或自动恢复；
- 双路或多路通信长期失效后的故障隔离、降级、重构和恢复；
- 通过故障注入验证系统保持安全状态、持续服务或恢复能力；
- 以故障持续时间、错误状态持续时间或恢复时间为触发条件的系统级恢复。

以下仍可属于接口测试：

- 对单帧或单次事务的ID、地址、长度、校验、索引和内容进行有效性判断；
- 无效数据对应的丢弃、不应答或错误应答；内部错误计数和日志不进入4.3；
- 请求无应答后结束当前事务、返回明确错误应答或记录该次事务失败，但不涉及硬件复位、链路重构或系统恢复。

判断标准：接口测试验证“跨边界传了什么、如何解释、无效数据怎样处理”；安全性/可靠性测试验证“通信设施故障后系统怎样检测、隔离、重构和恢复”。

## 时间要求边界

以下属于接口行为：

- 请求与应答的先后关系；
- 多帧索引和组帧顺序；
- 单次事务超时后结束该事务、返回错误应答、记录该次失败或禁止该次请求触发正常业务动作；
- 多帧事务未完成时放弃本次组帧，但不复位硬件、不重构链路且不执行系统恢复。

以下属于性能指标：

- 固定发送/采集周期；
- 响应时间或转换时间上限；
- 最小、最大、平均帧间隔；
- 延迟、抖动、吞吐率、传输速率、带宽和处理时限。

判断标准：4.3验证接口“做什么、怎样交互、错误时怎样处理”；性能测试验证“多快、多频繁、间隔多大”。

## 混合要求

对 `mixed` 要求：

1. 从 `interface_requirement_description` 和 `related_description` 中删除所有功能、性能及安全性/可靠性相关描述；
2. 仅保留独立且有证据支持的接口契约；
3. 如果剩余接口行为已被合法/非法字段、请求—响应闭环或同类处理族覆盖，则不再生成新行；
4. 如果原文的主要目的仍是故障检测、隔离、复位、重构或恢复，则整项不输出，不能通过删词把它改写成接口需求；
5. 不得把业务处理、内部存储、性能阈值或安全性/可靠性处置附加到接口需求描述或相关说明中。
