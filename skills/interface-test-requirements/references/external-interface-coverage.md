# 外部接口覆盖与系统特性规则

## 每个外部输入输出接口的基本覆盖

对当前接口标识下的每个外部输入、输出方向检查正常与异常情况，并从原文提取以下三类可测试要求：

1. **信息内容正确性**：请求—应答接口通过正常应答或明确的错误应答、不应答、丢弃验证第三章表格规定的报文是否合法；单向输出验证消息按对应表号发送。4.3不描述内部解析，也不重复表内格式定义。
2. **协议时序正确性**：请求与应答先后关系、多帧索引顺序、握手顺序以及超时后的明确功能处理是否正确；纯传输时间、周期、帧间隔、延迟和吞吐指标转交性能测试，不生成4.3需求。
3. **接口数据异常应答**：丢帧、错帧、误码、非法内容或其他原文明示的数据异常发生时，接口是否执行明确的错误应答、不应答或丢弃。内部错误计数、日志和业务动作不写入4.3；总线、控制器或收发器故障后的隔离、复位、重新初始化、冗余重构和自动恢复属于安全性/可靠性范围。

不得仅因为本规则列出某种异常就生成需求。原文没有异常类型、时间阈值或处理动作时，记录到 `open_questions`，不得使用协议常识补齐。

## 正常与异常成对组织

- 同一接口事务存在正常和异常证据时，在同一个需求行中引用请求与应答的第三章格式表号，描述正常应答，再逐项列出错误字段或异常类型及错误应答、不应答或丢弃；不得复制Byte/W布局、字段值、完整格式或接收后的内部处理。
- 禁止正文只描述正确情况，却在 `related_description` 中写“接口正常/异常情况的测试”。
- 只有正常证据时可以保留正常需求，但 `related_description` 只能声明正常测试，并在 `open_questions` 记录缺少异常条件或异常响应。
- 只有异常证据时只声明异常测试，不补造正常处理。
- 异常字段、无效条件和响应必须来自输入原文；覆盖清单只能发现缺口，不能提供项目事实。

接收后的数据处理、内部存储、业务状态更新和控制逻辑由功能测试覆盖。只有具有明确输出接口、接收方和输出格式的跨接口交付，才属于本节覆盖对象。

## 系统特性影响

检查接口的数据特性、错误特性和速度特性是否会影响软件功能或性能：

- 数据特性：数据范围、组合、边界、编码、精度、容量或数据量。
- 错误特性：只检查帧、字段、内容或单次事务错误的接口处理；系统级故障传播、故障隔离和恢复转交安全性/可靠性测试。
- 速度特性：仅检查速度异常是否触发明确的接口功能处理；周期、频率、吞吐、突发速率和处理时限本身属于性能测试。

只有输入文档给出具体特性及预期行为时才生成正式接口需求；否则写入 `open_questions`。

## 与其他测试类型的关系

- 配置项级接口测试重点覆盖全部外部接口。
- 内部接口主要通过功能和性能测试覆盖；输入明确要求内部接口专项测试时才生成接口测试项。
- 接口测试可与其他测试类型结合执行，但4.3需求只陈述接口数据、信号和事务契约；不得把性能、安全性或可靠性要求复制或改写进4.3。
- 对载人航天等明确要求“所有外部接口均测试”的项目，以接口标识清单为覆盖基线；任何接口标识没有正式需求行时，必须说明原因并写入 `open_questions`。
