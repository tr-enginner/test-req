# 关联与拆分规则

## 关联顺序

先从硬件接口文本确定接口实例、接口标识、通信主题、数据方向、消息/信号和格式，再使用消息名、指令名、字段名、站地址、计数器和动作关键词检索功能原文。

## 合并

以“完整业务事务”或“同类处理族”为合并单位，不以单个报文、单个方向或单张格式表为单位。

### 请求—响应闭环

请求报文和响应报文即使消息名称、格式和方向不同，只要满足以下条件，就合并为一个端到端接口需求：

- 属于同一次轮询、控制、查询、握手或数据交换；
- 响应由该请求直接触发，二者存在明确因果关系；
- 请求解析、响应生成和响应校验共同构成一个完成判据；
- 可以在一个测试场景中连续施加请求并观察响应。

合并后分别引用请求格式表和响应格式表，逐项保留请求校验、响应数量/索引、数据承载关系以及正常和异常结果；不得复制两张格式表内容，也不得只用“请求和响应正确”等概括行为。

### 同类处理变体

同一接口标识下的多个消息或数据分支仅在 ID/ID范围、地址、长度、索引、数据块数量、来源节点或数据内容布局上不同，而正常应答、错误字段集合和错误应答相同时，合并为一个处理族需求。正文只列消息名称、第三章表号、错误字段和应答差异；业务处理、内部存储、内部状态、错误计数和日志不参与建模。

合并前为每个候选建立处理签名：`interface_id + 通信方向和双方 + 正常应答 + 错误字段集合 + 错误应答`。签名相同则必须合并。快帧/慢帧、速变/缓变等名称或业务分类，以及ID、地址、长度、索引、数据块数量、载荷布局、格式表号、更新/采集/发送周期或可独立触发的差异均不改变处理签名；内部业务处理、错误计数、日志和状态差异也不参与签名。

正例：快帧遥测和慢帧遥测通过同一接口单向发送时，只生成一行；正文列出两种遥测、接收方及各自格式表号，不补造应答、周期或接收后的处理。

### 同类异常字段

接口和错误应答相同时合并多个异常字段。例如ID、DLC和SUM错误都导致不应答时可以合并，并逐项列出字段。

## 拆分

只有出现以下任一处理契约差异时拆分：

- 异常处理或可观察结果不同；
- 通信方向或双方不同且不构成同一请求—响应事务；
- 正常应答不同；
- 错误字段集合或错误应答不同；
- 普通指令与复位指令采用不同校验规则；
- 一个错误丢弃或不应答，另一个错误返回错误应答；
- 广播交替等正常接口事务不同。故障切换若主要验证系统故障检测、隔离、重构或恢复，则不进入拆分阶段，先按范围分类排除。

消息类型、业务分类、独立触发、格式表号、更新周期不同本身不是拆分理由。通信方向相反时先判断是否共同构成请求—响应闭环；ID、地址、长度或索引不同先判断是否属于相同处理族。

## 输出前语义最小化

写入 `rows` 前，对全部候选项做成对比较：

1. 是否属于同一interface_id，且能否归入同一请求—响应事务；
2. 合并签名是否相同，能否归入相同处理流程下的参数变体；
3. 合并后能否通过真实表号引用格式，并完整列出校验字段名和行为差异；
4. 删除其中一项是否会丢失独立触发、独立处理结果或独立异常后果。

前三项成立且第四项否时必须合并。目标是在不丢失明确字段、分支和处理规则的前提下，输出最少且完整的接口需求行。

不要机械地一字段一项，也不要把一段原文中的多个独立接口行为强行合并。
