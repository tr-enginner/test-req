# CAN 接口测试覆盖规则

本规则是覆盖检查清单，不是项目事实来源。仅当 `hardware_interface_report_text_path` 或 `source_artifacts_path` 引用的 document structure 能定位具体接口、字段、异常模式和预期行为时生成正式 row；证据不足时写入 `open_questions`。

## 覆盖基线

- 按“总线实例 × 输入流”检查；CANA、CANB 等明确总线实例分别形成完整覆盖。
- 同一接口标识下存在多个总线实例时仍保持一个 worker，在该批次内分别覆盖，不拆分接口标识。
- 覆盖每个明确输入流；不同长度的数据块需要逐项检查，但处理签名相同时合并到同一个接口TR中，不因长度或输入流名称单独拆行。
- 对每个输入流检查正常应答以及明确错误字段对应的错误应答、不应答或丢弃；不描述接收后的内部处理。

## 单帧与字段校验

从原文确认并逐项检查实际存在的字段：

- 仲裁场、控制场。
- 多帧帧序号及其起始值和连续性规则。
- `LENGTH`、`TITLE`、ID、地址、类型、索引及其他项目字段。
- 校验和或 CRC。
- DLC 与实际数据长度的一致性。

无效帧的处置只写原文明示的错误应答、不应答或丢弃。内部错误计数、日志和业务动作不写入正文；不得把字段清单当作证据，项目没有 `TITLE`、校验和或其他字段时不得补造。

输出到4.3时引用承载上述字段的第三章明确表号，不复制仲裁场、控制场、Byte/W位置、固定值、位域、字段编码或完整帧布局。字段名称只在描述合法性校验和异常响应时保留。

速变遥测轮询、缓变遥测轮询等原文明示为字节型数据的输入流，应检查逐字节错误注入；其他输入流按其实际字段检查。

快帧/慢帧、速变/缓变遥测等单向输出合并为一个发送处理族TR；列出消息名称、接收方及各自格式表号，不写周期、错误计数或对端处理。请求—应答类只有正常应答、错误字段集合或错误应答不同才拆分。

## 多帧专项

对多帧输入流检查：

- 首帧、中间帧、尾帧的字段错误。
- 帧序号错误或不连续。
- 未收到首帧、某个中间帧或尾帧。
- 仅收到前 N 帧，且 N 小于总帧数。
- 首帧、中间帧、尾帧的 DLC 小于实际长度。

还应检查事务隔离：故障多帧按原文明示执行错误应答、不应答或丢弃；其后到达的正确请求仍返回预期应答。不得描述残缺组帧状态等内部实现；具体外部响应必须来自项目原文。

## 高优先级广播插入

仅当项目原文明示 GPS 整秒对时广播或其他高优先级广播时，检查：

- 插入其他多帧输入流的帧间。
- 插入请求与应答之间。
- 插入后原事务的组帧、归属和后续处理符合项目定义。

不得仅凭本规则断言广播具有最高优先级，也不得编造插入后的继续、终止或恢复策略。

## 范围边界

- 格式、字段合法性、接收校验、请求—应答接口契约和无效输入处置属于 4.3。
- 指令内容对应的计算、业务执行、内部状态更新和存储属于 4.1。
- 总线/控制器故障检测、隔离、复位、重初始化、冗余重构和自动恢复属于安全性/可靠性测试。
- 周期、延迟、吞吐和定量响应时间属于性能测试；仅保留原文明示的接口先后关系。

## 输出前检查

- CANA、CANB 等明确实例是否分别覆盖。
- 每种输入流和长度块是否检查。
- 所有实际存在的格式字段是否覆盖正常值与错误值。
- 多帧是否覆盖位置错误、缺帧、残缺接收、DLC 异常及下一事务隔离。
- 高优先级广播是否在有证据时覆盖两类插入点。
- 未把公共覆盖项、协议常识或示例字段写成项目事实。
