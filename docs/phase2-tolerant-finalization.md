# Phase 2 复用与容错约定

prepare 按文件存在、可解析 JSON 和基础 schema 判断复用。JSON 读取统一支持 BOM、JSON 代码块、说明文本中的完整 JSON 对象及字符串以外的尾逗号；不覆盖模型原始 raw。来源是否存在、表格关联、上游修改时间和批次身份不参与复用决定。

finalize 保留有效正文，过滤未知来源，允许空来源或只有 supporting 来源。有效本地表自动补充唯一 ID，重复引用去重，共享表只展示一次，孤立表在所属功能项末尾展示；缺失源表、不可用 DOCX 表格资源或不匹配的表格列按单表跳过。

单目标内容使用当前任务的身份字段；多项内容按唯一标题编号、TR code、来源或标题匹配，身份冲突或重复归属时跳过。缺项保留标题并显示“内容未生成”。有效唯一需求编号保持不变，错误或重复编号重新分配，并避开编辑器停用的编号。

工作流统一返回：

- 成功或部分成功：`ok: true`、`warnings: string[]`、`skipped_count: number`，以及原有 output/summary。warnings 不表示执行失败；skipped_count 统计本次操作跳过的引用、表或内容，不代表缺失需求数量。
- JSON/schema 无法恢复、必需输入不存在或写入失败：`ok: false`、`error`。

已有 open_questions、gaps 和 warnings 字段保存相应诊断，不新增恢复协议文件。JSON/schema 失败后重新启动 Phase 2，prepare 会重新派发不合法 raw 对应的 worker；已合法 raw 保留复用。

source artifacts 等必要输入损坏以及磁盘、权限、文件占用等外部故障仍可能终止流程。生成文档完成不代表内容无缺项；调用方应展示 warnings。

## 编辑器与 DOCX 容错

finalize 成功写入 JSON 和对应报告后，将带版本的 `edit_mappings` 更新到现有 `phase2-editor-state.json`，保留编号序列和停用编号。映射记录实际处理链路中的 raw 位置、最终位置、身份及文件内容指纹；4.1 合并继承中间章节映射，不按最终数组位置反推 raw。映射通过原子替换发布，raw 不随 finalize 或描述接口改写。

编辑器以映射定位被修正编号或身份的条目，并校验 raw 与最终文件指纹。用户保存后需重新 finalize 再继续使用新产物；旧映射不会被静默复用。无映射旧项目仅接受唯一匹配；歧义或过期目标拒绝修改。没有 raw 的缺项占位返回 `editable: false` 与 `disabled_reason`。路径白名单、revision 和编号冲突保护保持生效。

描述接口返回过滤后的来源视图，并提供 `warnings`、`skipped_count`。来源目录缺失或损坏不阻断其他内容展示和无关字段修改；显式空来源可保存。目录不完整时，非空来源修改拒绝保存，未编辑来源原样保留。缓存签名包含缺失文件状态，文件恢复后重新加载。

功能 DOCX 渲染使用表格归一化副本；自动表格引用在表格成功构造后才写入。失败表每次渲染只尝试一次，共享成功表复用表号。硬件旧产物的非法接口 ID 在渲染副本内补充稳定 ID，不修改输入文件。独立前端组件不属于本仓库修改范围。
