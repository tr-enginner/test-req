# 代码审查智能体中基于代码切片的代码审查技术设计

## 3.1 关键技术分析

代码审查智能体面向嵌入式 C/C++ 程序中的典型常见多发问题检测，重点覆盖中断数据访问、数组越界、未初始化变量使用、数值溢出等风险。其输入主要包括目标范围内的源代码文件、软件分析阶段形成的函数与关联信息、编译环境描述信息以及从源代码中抽取的行为相关上下文；其输出则为分批次的审查结果以及按源文件汇总的最终审查记录。与一般规则检查不同，此类问题通常与调用关系、数据传播和控制路径相关，具有明显的跨函数、跨上下文特征，因此其关键不在于局部语句匹配，而在于围绕风险链条构造合理的分析上下文。

该问题的核心难点在于分析粒度的选择。若按函数逐个分析，容易割裂中断访问链、数组索引传播链和数值运算链，导致风险难以完整识别；若按整文件直接分析，又会引入过多无关代码，增加语义噪声，削弱模型对关键问题的聚焦能力。因此，代码审查智能体的关键技术瓶颈，不在于是否能够分析代码，而在于是否能够建立一种兼顾上下文完整性与输入规模可控性的上下文组织机制，从而支撑典型高发问题的稳定检测。

## 3.2 关键技术解决途径

针对上述问题，本文采用“代码切片优先、源文件级回退”的技术路线。整体上，通过语法解析、行为相关切片构建以及分批结果汇总三个环节，形成面向典型代码审查问题的审查闭环。具体技术解决途径如下。

（1）基于 Tree-sitter 的程序事实抽取技术。  
首先利用基于抽象语法树的语法分析方法对 C 源代码进行解析，并借助 `tree-sitter` 提取函数定义、调用关系、全局变量定义、类型定义等基础事实信息。在此基础上，将程序中的函数、调用、类型和共享状态信息组织为结构化索引，为后续代码切片和上下文构建提供统一的数据基础。通过这一过程，可以为中断数据访问、数组越界、未初始化使用和数值溢出等问题提供必要的程序结构信息与语义依赖信息。

（2）基于分批执行与回退机制的代码审查组织技术。  
在完成基础事实抽取后，系统优先围绕调用关系与共享状态构造行为相关代码切片，并以切片作为基本审查单元；当切片构建失败或无法提供有效上下文时，则退化为按源文件组织审查单元，以保证审查流程稳定执行。每完成一个分析单元，系统即生成对应的批次审查结果，并在全部分析完成后按源文件进行汇总，形成最终审查记录。通过这种“切片优先、文件回退、结果汇总”的组织方式，可以在保留关键行为语义的同时控制输入规模，并保证代码审查过程具备可执行、可跟踪和可汇总的工程属性。

（3）面向典型审查项的代码审查设计技术。  
代码审查并非针对全部代码内容做平均展开，而是围绕中断数据访问、数组越界、未初始化变量使用、数值溢出等典型常见多发问题组织审查重点。对于中断数据访问问题，重点审查中断上下文与普通执行流之间的共享变量读写关系；对于数组越界问题，重点审查索引来源、边界判断与目标访问之间的传播关系；对于未初始化变量使用问题，重点审查变量的定义、赋值与使用链路；对于数值溢出问题，重点审查连续运算、类型转换和结果传播过程。通过将审查目标聚焦于上述典型问题，并利用代码切片保留相关语义链条，可以提高代码审查的针对性和有效性。
