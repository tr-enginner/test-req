# 功能测试接口模型与翻译边界

功能测试仍由 `test-functional.md` 生成，通过 `{{INTERFACE_SECTIONS}}` 复用接口分节；测试类型与接口操作模型是两个不同维度。生成清单记录 `functional_model` 和 `interface_sections`，用于核对实际采用的规则。

| 需求 | 操作模型 |
| --- | --- |
| 引导加载、初始化 | 保留人工操作和检查步骤，不做关键字匹配、参数绑定、翻译 |
| Spacewire 上注接收 | 每块分别写协议数据、写 ID、触发指定外部中断 |
| SPI／二级 CAN 遥测采集 | 一级 CAN 周期发送对应遥测帧轮询控制序列以回读验证；模拟对应接口输入；软件轮询触发按测试需要和需求依据另行添加 |
| FPGA 状态遥测采集 | 先写输入地址，再轮询相关遥测验证位域映射 |
| 相机辅助数据发送 | 配置指令作为测试输入；二级广播及周期、字段变化作为预期输出 |
| 249 字节上行数据块 | 正确第一包→同包错误→正确第二包→同包另一错误→正确最后一包→同包再一错误，完整轮次推进 |

有序多包在所有包之间分摊错误覆盖，最后一轮不足的部分只补齐正确包；双辅助数据包仍保留原有四步模型及两包分别覆盖要求。不能混淆包序号与包内帧序号，实际帧数取输入格式表。

人工用例的 `translate_status` 为 `not_applicable`，步骤保留源文与预期，`key_name` 为空、`parameter` 为空数组，并标记 `translation_exempt_reason=manual_requirement`。这不是翻译失败，也不是自动化翻译成功：用例仍进入报告和设计覆盖统计，但 DTP／Robot 只选择 `success`。免翻译由需求身份确定，不接受任意 worker 自报豁免；其他需求正文或前置条件提及“初始化”不会触发此策略。

格式校验和 reviewer 预检查共享模型检查，对错误通道、缺失三步交付、错误有效包序列等返回重派原因。专属模型违规不通过机械补发、补触发绕过。共享中断表及跨需求引用可提供参数事实，但不能据此把其他接口模型注入当前功能需求。

一级周期回读与软件轮询触发是两个独立动作。自主轮询只免除不必要的触发，不免除回读；回读覆盖用例涉及的各遥测帧（含错误计数），同一帧只启动一次循环。模拟返回时间仍由真实 SPI／二级 CAN 轮询顺序决定，不能根据一级回读周期臆造。

关键字翻译以步骤实际动作优先于 operation_type、step_plan 及预期结果。中断触发不得降级为发送；无兼容关键字时报告失败。载荷按括号/引号配对提取，保留嵌套限定条件并同时写入 step_desc 与数据文件参数，不能遇到括号内逗号即截断。
