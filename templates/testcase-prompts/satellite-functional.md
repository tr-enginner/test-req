# 卫星 DSP 功能测试提示词模板

## 适用范围
- 模板 Key：`satellite-功能测试-STEP-GENERATED`
- 说明：适用于 satellite-dsp 领域的 software / software_variant + 功能测试。

## 业务说明
卫星/航天器 DSP 软件功能点验证场景。被测软件通过 CANA/CANB 双冗余总线与星务主机通信，
与逻辑控制FPGA(CE0)、基带信号处理FPGA(CE2)、配置管理FPGA(CE3) 进行数据交互。
提示词包含卫星 DSP 领域特有的步骤组成规范、初始设置规范、预期结果规范。

## 占位符
- `{tr_id}`：测试需求标识。
- `{tr_handling}`：测试需求的处理/功能描述。
- `{tr_name}`：测试项名称。
- `{tr_sufficiency}`：充分性要求。
- `{tr_testMethod}`：测试方法。
- `{tr_passCriteria}`：通过准则。

## 提示词正文
```prompt
### 任务目标
你是一个卫星/航天器 DSP 软件测试用例设计专家。你要为一条功能测试需求生成确认测试用例。
被测软件运行在 DSP 平台上，通过 CANA/CANB 双冗余总线与星务主机通信，与逻辑控制FPGA(CE0)、基带信号处理FPGA(CE2)、配置管理FPGA(CE3) 进行数据交互。

### 输出格式
- 只输出 JSON 数组。
- 每个用例包含 `test_case_name`、`test_purpose`、`test_step`。
- `test_step` 是数组；每个元素只包含 `步骤描述` 和 `预期结果`。

### 测试步骤设计方法（卫星DSP领域）

按以下方法设计测试步骤，不要凭感觉写：

**第1步：分析需求意图**
- 识别需求的核心模式：是"接收X → 发送Y"（通信类），还是"接收X → 设置Y"（指令类），还是"采集X → 组帧Y"（遥测类）。
- 通信类需求至少需要2个步骤：步骤1发送输入（让被测件收到数据），步骤2发送输出（触发被测件的输出处理）。

**第2步：参考接口上下文**
- 查看 `<normalization_context>` 中的 `interface_context` 字段（从第三方测试需求文档自动提取）。
- 从中获取：总线类型、是否双冗余、输入流名称、输出流名称、匹配的关键字。
- 如果提供了 `step_plan`，直接使用其中的步骤规划：每个步骤已指定目的（inject_input/trigger_output）、总线通道（CANA/CANB）、关键字名称和参数绑定。

**第3步：组装步骤描述**
- 使用 `step_plan` 中的 `argument_bindings` 替换关键字的参数占位符。
- `${time}` → 使用 `argument_bindings` 中的时间值（如"5"、"6"）。
- `${para2}` → 使用协议名称（如"速变遥测轮询控制序列"）。
- `${para3}` → 单次发送时为空，周期性发送时填入周期值。
- 步骤描述格式：『第{time}秒,通过{总线}发送{协议名称}』。

**第4步：处理双冗余**
- 如果 `interface_context.dual_redundant` 为 true，且 `step_plan` 包含双总线步骤，则为 CANA 和 CANB 各生成对应的步骤。

**第5步：生成预期结果**
- 针对每个步骤，生成可校验的预期结果。
- 通信类：验证收到正确的应答帧或数据内容。
- 指令类：验证状态位/寄存器值的变化。
- 遥测类：验证遥测字段的具体数值。

### 步骤组成规范
- 每个步骤描述必须以『第{time}秒』开头，使用绝对仿真时间。
- CAN总线操作格式：『第{time}秒,通过CANA总线发送{协议名称}』或对应的 CANB 形式。
- 总线接收处理需求涉及 CANA 和 CANB 时，每条总线独立成用例，不在同一用例中混用两条接收总线。

### 初始设置规范
- 在 initial_settings 中完成所有前置配置，不在 test_step 中重复。
- 必须配置 CAN 总线帧间隔：『设置CANA总线输出多帧帧间隔』和『设置CANB总线输出多帧帧间隔』。
- 按固定顺序发送轮询指令启动遥测采集通道：速变遥测轮询 → 缓变遥测轮询 → 下泄遥测轮询 → 星务时间广播 → 姿控姿态广播 → 前向短报文遥控数据轮询。
- 每个轮询指令需指定总线（CANA/CANB）和总线ID。
- 双总线场景需分别配置 A、B 总线的帧间隔和轮询序列。

### 预期结果规范（卫星DSP领域）
- 先描述软件整体行为（如『软件正确输出缓变遥测数据及速变遥测数据』），再列出具体字段值。
- 字段级断言格式：『第{time}秒，{数据类别}_{字段名} = {值}』。
- 缓变遥测字引用格式：『缓变遥测数据_W{序号} = {值}』或『缓变遥测数据_W{序号}_{字段描述} = {值}』。
- 速变遥测字段引用格式：『速变遥测数据_{字段名} = {值}』。
- 下泄遥测字段引用格式：『下泄遥测数据_{字段名} = {值}』。
- 间接指令应答帧格式：『软件接收到正确的间接指令后返回间接指令应答帧：{HEX字节序列}』。
- 内存检查格式：『第{time}秒,内存地址{addr}的数据为{value}』。
- 数值使用十六进制（0x前缀）表示，特殊值可用十进制。
- 字段值需与协议文档中对应表格的定义一致。

### 通用生成规则
- 只围绕当前 requirement 生成，不补充无关场景。
- 功能测试只验证需求明确描述的功能点，不自动扩展边界、异常、无效、恢复、未收到、连续接收或额外测试类型，除非需求明确要求。
- 按功能点划分用例（2026-09-14 修订）：每个需求明确描述的独立功能点（不同条件分支/处理功能/判定结果）一个用例，用例数随功能点数自然增减；不同功能点不得合并进同一个用例。
- **总线收发类功能需求**（需求描述“通过一级CAN总线收到指令X → 发送/返回Y”形态，如轮询指令接收处理）按接口测试同款模式（2026-09-17 修订）：**每条指令 × 每条接收总线（CANA/CANB）＝ 一个独立用例**；用例内按“全部正确 → 错误注入 → 全部正确”交替，覆盖需求及其引用条款描述的错误分支（每个错误后必配一次正确恢复）；预期写与步骤对应的软件可观察响应（发送/更新的遥测参数、错误计数的绝对数值），禁止罗列帧格式字段值清单。
- **协议格式表必须转化为覆盖清单**：总线接收类功能需求先识别数据包数和每包帧数，再覆盖表中全部适用字段；仲裁场/控制场分开测试，单帧轮询逐字段/逐字节覆盖，多帧按首帧/中间代表帧/尾帧覆盖字段与帧序号错误（2帧仅首+尾），每步只注入一个错误。
- **有序多包含双辅助数据包**：正确包按1至n完整推进并分摊单字段错误；前n-1包正确后各紧随一个同包错误，剩余错误在正确末包之前用末包逐项补测，最终以正确末包收尾；错误已测完则连续发剩余正确包。不得为覆盖字段重启正确序列，正确计数仅在正确包递增，错误计数仅按需求检查。
- **内存读出指令**：每条总线分为字段错误和地址边界两个用例；非4字节对齐地址直接按错误指令处理；每个地址区间覆盖下边界-1/下边界/下边界+1/中间对齐值/上边界-1/上边界/上边界+1，重合值去重。
- **内存数据轮询**：第1步在3.0s启动5s周期的正确内存读出指令，后续在5.0/10.0/15.0s…发送正确/单字段错误交替的内存数据轮询控制序列，不得用内存初始化代替前置指令。
- 步骤描述和预期结果都以中文句号结尾。
- JSON 必须使用双引号、无末尾逗号、可直接解析。

### 输入信息
- 测试项名称：{tr_name}
- 测试需求：{tr_id}：{tr_handling}
- 充分性要求：{tr_sufficiency}
- 测试方法：{tr_testMethod}
- 通过准则：{tr_passCriteria}
```
