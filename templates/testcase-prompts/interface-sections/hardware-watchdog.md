# 硬件狗(看门狗)接口专属规则——检测到 硬件狗/看门狗/喂狗 需求时注入

### 看门狗用例固定模式（强制，2026-09-08 用户拍板）

看门狗接口的测试用例形态**固定**（靠示波器实测清狗间隔，测试环境由系统固定为"硬平台测试环境"，不要在用例中另写环境字段）：

1. **测试目的**（逐字，仅替换端口号占位）：
   `测试软件清看门狗时间间隔（即<看门狗相应端口号>相邻两次写操作的时间间隔）的情况；考虑了插入中断的最坏情况。`
2. **测试步骤**（逐字，单步）：
   `使用示波器多次测试清看门狗时间间隔（即<看门狗相应端口号>相邻两次写操作的时间间隔）。`
3. **预期结果**（逐字）：
   `软件清看门狗时间间隔最大不超过<清看门狗最大时间>s。`

**优先级声明**：本节是固定句式专属规则，**优先于**通用的"预期结果写绝对值/占位符必须解析"要求——"清看门狗最大时间"是设计裁定的保留字面文本，不是待解析占位符（需求上下文通常只有狗咬时间，把它填进去就是错误）。本用例由示波器人工实测，**不需要关键字匹配、不需要可执行参数**（key_name 留空、parameter 留空是预期形态），单用例单步骤即完整交付。

**占位符取值规则**：
- `<看门狗相应端口号>`：从需求的喂狗端口定义逐字取（如"通过BM3803的PIO12写操作实现喂狗"→`PIO12`）；
- `<清看门狗最大时间>`：是按需求设置的**小于狗咬时间**的值——需求上下文通常只给狗咬时间（如"狗咬时间为1.8s"），**不得把狗咬时间当清狗最大时间填入**；上下文无法确定具体值时保留文本`清看门狗最大时间`。
- 一条看门狗需求一个用例，不扩展上电/复位/多发等其他场景。

标准示例（端口取自需求定义，下例以 PIO12 示意；需求只给了狗咬时间 1.8s，未给清狗最大时间）：
```
测试目的：测试软件清看门狗时间间隔（即PIO12相邻两次写操作的时间间隔）的情况；考虑了插入中断的最坏情况。
测试步骤：使用示波器多次测试清看门狗时间间隔（即PIO12相邻两次写操作的时间间隔）。
预期结果：软件清看门狗时间间隔最大不超过清看门狗最大时间s。
```

禁止（反例）：
- 把狗咬时间（如 1.8s）填进预期结果（狗咬时间≠清看门狗最大时间）；
- 改写固定句式（目的/步骤/预期三段逐字保留，仅替换占位符）；
- "软平台自适应改写"（2026-09-08 二次取证纠错形态）：把固定步骤改写成内存写喂狗步骤（如"第1.0秒，设置内存地址PIO12_GPIO_DATA_REG_H的数据为0x01（通过PIO12写操作触发喂狗动作）"）、自造端口寄存器地址、生成多条写步骤、或写"硬件时序测量由硬平台/鉴定测评补充完成"类推迟表述——本用例在软平台生成、硬平台执行，**禁止任何自适应改写**；
- 扩展喂狗写操作步骤、上电/复位步骤或拆分多个用例（形态固定，单用例单步骤）；
- 在用例中自行填写"软平台测试环境"（环境由系统统一处理）。
