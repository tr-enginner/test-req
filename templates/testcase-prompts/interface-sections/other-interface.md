# 其它(其他)接口兜底专属规则——检测到 其他接口/其它接口 + 遥控指令 + PIO/脉冲输出 需求时注入

### 其它接口一级遥控指令收发模型（强制，2026-09-08 用户拍板，与秒脉冲/成像控制同构）

"其它接口"需求无法归入具体接口类，但其数据流若呈"**收到某遥控指令 → 通过 PIO 口输出脉冲/信号**"形态（如平台CAN总线复位指令→PIO口复位脉冲），按**一级总线遥控指令收发模型**处理——数据流定义中的 PIO 口/脉冲参数属于**软件的输出流**，不是测试系统的写内存输入：

1. **步骤形态**："第N秒，通过CANA总线发送正确的平台CAN总线复位指令"。该指令是**遥控指令**——上下文未给出具体指令代号与字段编码，载荷名逐字用需求定义的指令名（如"平台CAN总线复位指令"），**禁止编造指令代号或字段值**（字段取值由执行阶段的数据文件承载）。
2. **字段错误遍历（W0~W9）**：对遥控指令的 W0~W9 字段逐一测试错误形态："第N秒，通过CANA总线发送平台CAN总线复位指令（W0字段错误，其余字段正确）"……每个字段各一步；**正确-错误交替**——每个错误步骤后紧跟一条正确指令步骤恢复（结构检查按同指令同总线配对判定，交替缺失会被拦截）。
3. **预期结果**：所有步骤一律"软件通过CANA总线返回遥控指令应答"（按实际发送总线写）；**发送正确指令的步骤额外写"通过对应的PIO口输出对应的总线复位脉冲信号（脉冲大于100us）"**——PIO 映射与脉宽参数逐字取数据流定义（如 CANA→PIO3、CANB→PIO7，负脉冲>100us）。
4. **双总线各自独立用例**：需求同时覆盖 CANA 与 CANB 的复位端口时，**每条总线各一个独立用例**——CANA 用例预期 PIO3 复位脉冲、CANB 用例预期 PIO7 复位脉冲，不得混在同一用例。
5. 首个业务步骤**从第3.0秒开始**，禁止第0.0秒。

标准示例（PIO 映射取数据流定义；W0~W9 仅示意前两字段，其余同理；CANA 用例，CANB 用例同构换总线与 PIO 口）：
```
(1) 第3.0秒，通过CANA总线发送正确的平台CAN总线复位指令；预期：软件通过CANA总线返回遥控指令应答，通过PIO3输出对应的一级CANA总线复位脉冲信号（脉冲大于100us）
(2) 第4.0秒，通过CANA总线发送平台CAN总线复位指令（W0字段错误，其余字段正确）；预期：软件通过CANA总线返回遥控指令应答
(3) 第5.0秒，通过CANA总线发送正确的平台CAN总线复位指令；预期：软件通过CANA总线返回遥控指令应答，通过PIO3输出对应的一级CANA总线复位脉冲信号（脉冲大于100us）
(4) 第6.0秒，通过CANA总线发送平台CAN总线复位指令（W1字段错误，其余字段正确）；预期：软件通过CANA总线返回遥控指令应答
（W2~W9 依此类推：每个字段错误一步，错误后紧跟一步正确指令恢复）
```

禁止（反例）：
- 把输出流写成写内存步骤或设置类步骤（PIO 口/脉冲参数是软件输出，不是测试系统输入）；
- 编造指令代号或载荷字段值（由执行阶段数据文件承载）；
- CANA 与 CANB 复位混在同一用例（每条总线独立用例，PIO 口各自对应）；
- 错误步骤后不跟正确恢复步骤（正确-错误交替是硬约束，会被结构检查拦截）；
- 正确指令步骤的预期漏写 PIO 口复位脉冲输出；
- 首个步骤时间为第0.0秒。
