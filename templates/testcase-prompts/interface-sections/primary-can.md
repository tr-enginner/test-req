# 一级CAN 帧协议接口专属规则——检测到 CAN 信号或无其他接口信号时默认注入

适用范围：仅约束本需求实际经过一级 CAN 的测试输入，不能把 SPI、二级 CAN、Spacewire 或内存输入改写成一级 CAN 发送。有序多包（含双辅助数据包）统一规则优先于下文同包恢复编排；强度测试的单综合用例、单步单指令及相邻合法/非法约束优先于本节通用拆例规则。帧数始终从格式表统计，示意数字不得当作协议事实。

### 类型专属规则

**生成前必须检查（逐条确认，不可遗漏）**
1. 查看输入流说明中的指令数据格式表格，统计每个指令的总帧数。
2. 如果某指令的帧数≥2，则该指令为多帧指令，必须同时满足以下两点：
   a. **字段错误只测3帧（首帧+尾帧+中间任选一帧），不可穷举全部N帧**：对帧数≥3的多帧指令，只选首帧、尾帧和中间任意一帧做字段错误测试；普通独立包按"全部正确→仲裁场错→全部正确→控制场错→全部正确"编排，有序多包按专属模型推进正确包。帧数和中间代表帧编号从实际格式表确定，不得将249字节数据块固定假设为12帧。2帧指令只测首帧和尾帧。
   b. **帧序号错误必须覆盖（按帧数区分）**：2帧指令覆盖6类（首帧3类+尾帧3类）；3帧及以上指令覆盖9类（首帧3类+尾帧3类+中间帧3类）。（见下方帧序号错误详细说明）。
3. 如果某指令的帧数=1，则只需对该帧做字段错误测试，无需帧序号错误测试。
4. 在每生成一个测试用例前，在脑中先过一遍：这个用例测的是哪帧的什么错误？是否首帧、尾帧、中间帧（3帧）都已覆盖？帧序号错误覆盖数量是否与帧数匹配（2帧=6类、3+帧=9类）？

**用例拆分原则**
- 每条指令+每条总线生成一个测试用例。该用例包含该指令的所有异常测试：仲裁场错、控制场错、帧序号错（如适用）。
- 格式不同或字节长度不同的指令/数据块拆分为不同用例，且步骤载荷必须带长度限定词**逐字使用数据流定义名**（如"10字节遥控指令"与"15字节遥控指令"、"249字节上行数据块"与"72字节上行数据块"各立独立用例）——禁止裸写"遥控指令""上行数据块"这类不带长度的泛名（不指明长度无法确定测的是哪种格式，会被结构检查拦截）。
- 双冗余总线时，每条总线各自一个用例。

**异常测试步骤编排**
- 每个测试步骤只允许一个字段错误，步骤按"全部正确 -> 某一字段错误 -> 全部正确 -> ..."交替组织。
- 同一指令的所有异常测试（仲裁场错、控制场错、帧序号错）全部合并到一个测试用例中。步骤按以下顺序组织：
  1. 发送所有帧正确的数据（初始正确步骤）
  2. 对首帧：仲裁场错 → 正确 → 控制场错 → 正确
  3. 对尾帧：仲裁场错 → 正确 → 控制场错 → 正确
  4. 如果总帧数≥3，从中间随机选一帧：仲裁场错 → 正确 → 控制场错 → 正确
  5. 帧序号错（2帧=6类、3+帧=9类），每类后跟正确步骤（见下方帧序号错误详细说明）
- 如果总帧数=2（无中间帧），则跳过第4步中间帧测试和第5步中涉及中间帧的序号错误，只需测试首帧+尾帧的字段错误和首帧/尾帧的序号错误。
- 帧序号错只在多帧（≥2帧）输入流时测试，单帧跳过。

**步骤描述一致性要求**
- 同一个测试用例中，所有步骤的描述风格和标注粒度必须保持一致：载荷名统一带长度限定词（如"249字节上行数据块"）、正确步骤统一含"正确的"、字段错误步骤统一用"（XX错误，其余字段正确）"标注；不允许前面步骤标注具体、后面步骤只用概括性描述。预期结果同理。
- 一致性指**情况描述**粒度，不是罗列字段值——步骤描述仍然禁止给出"仲裁场=8DH、控制场=04H"之类的具体字节取值（字段取值由执行阶段的数据文件承载）。

**预期结果字段判断规范**
- 预期结果中，能够通过上下文直接确定的字段值必须明确写出具体数值（如"仲裁场=8DH，控制场=68H"），不能确定的字段值不要提及，不要凭空编造。
- 对于多帧输出的预期结果：首帧中能够确定的字段明确写出具体值；后续帧中如果帧序号递增但帧内数据无法确定，只需描述帧序号的变化规律。不要使用"后续参数帧依次输出"这样的含糊表述。总帧数描述为"共输出N帧"。

**校验和**
- 校验和请按照规定的校验和计算方法计算，不要编造校验和值。

### 帧序号错误详细说明（9类，替代原来的4类）

帧序号字段位于每帧仲裁场和控制场之后的第一个字节。帧序号最大值为总帧数-1，从0开始。

**首帧错误场景（3类）— 正确帧序号为00H：**
1. **首帧重复**：前面2帧的帧序号都是00H（多发送一帧），接下来的帧必须是01H~最大正确帧序号。（数据包帧数：正确帧数+1）
2. **首帧帧序号错误**：第一帧帧序号≠00H（如改为01H），接下来帧序号为01H~最大正确帧序号。（数据包帧数：正确帧数）
3. **首帧丢失**：第一帧帧序号为01H（跳过00H），接下来帧序号为02H~最大正确帧序号。（数据包帧数：正确帧数-1）

**尾帧错误场景（3类）— 正确尾帧序号为最大值（总帧数-1）：**
4. **尾帧重复**：前面帧序号为00H~最大值-1，最后2帧的帧序号均为最大值（多发一帧）。（数据包帧数：正确帧数+1）
5. **尾帧帧序号错误**：前面帧序号正常，最后一帧帧序号为最大值之外的其他值。（数据包帧数：正确帧数）
6. **尾帧丢失**：所有帧的帧序号为00H~最大值-1（缺少尾帧）。（数据包帧数：正确帧数-1）

**中间帧错误场景（3类）— 仅当总帧数≥3时适用：**
7. **中间帧重复**：前面帧序号为00H~正确中间帧序号，当前帧帧序号与前一帧相同，后面帧序号继续递增。（数据包帧数：正确帧数+1）
8. **中间帧帧序号错误**：前面帧序号正常，当前帧序号为正确值之外的其他值（不连续），后面帧序号跳过该位置继续。（数据包帧数：正确帧数）
9. **中间帧丢失**：前面帧序号为00H~正确中间帧序号，下一帧序号直接跳到正确中间帧序号+2。（数据包帧数：正确帧数-1）

### 遥测轮询逐字节错误（条件规则）

**仅当需求项的"处理"字段中明确提及遥测轮询控制序列逐字节校核时**才适用此规则：

遥测轮询控制序列一般是单帧短数据，每个字段都是确定的值且字节数较少。需要逐个字节考虑每个字节错误的场景。

例如：遥测帧1轮询控制序列数据为 `8DH 04H 00H 10H 01H 11H`（共6字节），则需要为每个字节设计一个错误场景：

- 步骤编排：第1字节正确→第1字节错→正确→第2字节错→正确→...→第6字节错→正确
- 每个错误步骤只改变当前测试字节的值（如将正确值改为相邻值或翻转某位），其余字节保持正确
- 此规则仅适用于遥测轮询控制序列（单帧），不适用于多帧指令

若需求未提及逐字节校核，此规则不适用，跳过即可。

### LENGTH 字段错误（条件规则）

**仅当需求项的"处理"字段中明确提及 LENGTH 字段错误校核时**才适用此规则：

LENGTH 位于仲裁场、控制场、帧序号之后的第1个字节。其值为整包数据中有效数据的字节数。例如内存读出指令的 LENGTH 为 0AH，表示数据包中含有 W0~W9 这 10 个有效数据。

- 对于多帧指令/数据，需要测试 LENGTH 错误的情况。编排策略与字段错误一致：正确→LENGTH错→正确

若需求未提及 LENGTH 校核，此规则不适用，跳过即可。

### DLC 字段错误（条件规则）

**仅当需求项的"处理"字段中明确提及 DLC 字段错误校核时**才适用此规则：

DLC 为控制场的低4位（如 04H 表明该帧有效数据场长度为 4 字节）。例如遥测帧1轮询控制序列 `8DH 04H 00H 10H 01H 11H`，控制场 04H 之后的 4 字节为有效数据场。

- 测试 DLC 小于实际数据长度时系统的处理。编排策略与帧序号一致：首帧/中间帧/尾帧各测 DLC 错误（单帧指令只测该帧）

若需求未提及 DLC 校核，此规则不适用，跳过即可。

### GPS 整秒对时广播高优先级插入（条件规则，新增）

**仅当输入流中包含星务时间广播数据（GPS 整秒对时广播）时**才适用此规则：

1. **插入接收与应答之间**：测试其他遥测轮询、指令或数据时，在接收指令/数据和应答之间插入 GPS 整秒对时广播。预期结果为：正确处理 GPS 整秒对时广播 + 输出处理完接收之后的对应应答。
2. **插入多帧数据之间**：测试多帧指令或数据时，在多帧数据帧之间插入 GPS 整秒对时广播。预期结果为：正确处理 GPS 整秒对时广播 + 继续输出对应应答。

若输入流中不包含星务时间广播数据，此规则不适用，跳过即可。
