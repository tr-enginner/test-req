# 成像控制接口(软件↔FPGA 转发)专属规则——检测到 转发成像控制信号指令/输出流成像控制信号 需求时注入

### 成像控制接口测试模型（强制，2026-09-08 用户拍板，与秒脉冲接口同构）

成像控制接口的数据流定义虽给出地址（21144000H），但该地址属于**输出流**——软件收到成像控制信号指令后通过该地址输出成像控制信号的监视地址，**不是测试系统的写内存输入**；软件经 FPGA 接口转发、FPGA 依据该地址输出通道控制信号都是**软件/FPGA 内部动作，不是测试步骤**。测试模型是**一级总线遥控指令收发**：

1. **步骤形态**："第N秒，通过CANA总线发送正确的成像控制信号指令"。成像控制信号指令是**遥控指令**——上下文未给出具体指令代号与字段编码，载荷名逐字写"成像控制信号指令"，**禁止编造指令代号，禁止在步骤中罗列通道选择清单或位取值**（如"选择对地高分红外短波通道、…四个通道"“D7=1”之类——通道组合与字段取值由执行阶段的数据文件承载）。
2. **字段错误遍历（W0~W9）**：对遥控指令的 W0~W9 字段逐一测试错误形态："第N秒，通过CANA总线发送成像控制信号指令（W0字段错误，其余字段正确）"……每个字段各一步；**正确-错误交替**——每个错误步骤后紧跟一条正确的成像控制信号指令步骤恢复（结构检查按同指令同总线配对判定，交替缺失会被拦截）。
3. **预期结果**：所有步骤一律"软件通过CANA总线返回遥控指令应答"；**发送正确指令的步骤额外写"通过地址21144000H输出对应的成像控制信号"**（地址逐字取本需求输出流定义；信号各位的具体取值由软件行为决定，不在预期中罗列位值清单）。
4. 首个业务步骤**从第3.0秒开始**，禁止第0.0秒。

标准示例（地址取数据流定义值，下例以 21144000H 示意；W0~W9 仅示意前两字段，其余同理）：
```
(1) 第3.0秒，通过CANA总线发送正确的成像控制信号指令；预期：软件通过CANA总线返回遥控指令应答，通过地址21144000H输出对应的成像控制信号
(2) 第4.0秒，通过CANA总线发送成像控制信号指令（W0字段错误，其余字段正确）；预期：软件通过CANA总线返回遥控指令应答
(3) 第5.0秒，通过CANA总线发送正确的成像控制信号指令；预期：软件通过CANA总线返回遥控指令应答，通过地址21144000H输出对应的成像控制信号
(4) 第6.0秒，通过CANA总线发送成像控制信号指令（W1字段错误，其余字段正确）；预期：软件通过CANA总线返回遥控指令应答
（W2~W9 依此类推：每个字段错误一步，错误后紧跟一步正确指令恢复）
```

禁止（反例）：
- 把输出流地址写成写内存步骤："第3.5秒，CPU软件将成像控制信号数据通过FPGA接口转发，写入FPGA地址21144000H"（输出流地址不是写内存输入，且软件内部转发动作不是测试步骤，2026-09-08 取证纠错形态）；
- 把 FPGA/软件内部行为写成测试步骤或读取类步骤："FPGA根据地址21144000H的成像控制信号数据输出通道控制信号"（FPGA 行为属于预期结果，不是测试系统操作）；
- 编造指令代号、载荷字段值或位取值清单（"0x00000AC5""D31~D8填充00000AH""选择…四个通道"等由执行阶段数据文件承载）；
- 错误步骤后不跟正确恢复步骤（正确-错误交替是硬约束，会被结构检查拦截）；
- 正确指令步骤的预期漏写"通过地址21144000H输出对应的成像控制信号"；
- 首个步骤时间为第0.0秒。
