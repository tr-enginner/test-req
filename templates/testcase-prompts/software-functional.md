# 软件功能测试提示词模板

## 适用范围
- 模板 Key：`功能测试-STEP-GENERATED`
- 说明：适用于 software / software_variant + 功能测试。

## 业务说明
用于软件功能点验证场景。 提示词正文已收敛为短结构，业务人员如需优化，优先调整“类型专属规则”和“输入信息”的表达，不要在 `prompt` 代码块中加入大段示例或教学说明。

## 占位符
- `{tr_id}`：测试需求标识。
- `{tr_handling}`：测试需求的处理/功能描述。
- `{tr_name}`：测试项名称；仅在正文中出现时需要保留。
- `{tr_sufficiency}`：充分性要求。
- `{tr_testMethod}`：测试方法。
- `{tr_passCriteria}`：通过准则。
- `{tr_input_flow}`：输入流说明。
- `{tr_output_flow}`：输出流说明。
- 若正文中未使用某个占位符，可忽略对应说明。

## 提示词正文
```prompt
### 任务目标
你要为一条功能测试需求生成确认测试用例。

### 输出格式
- 只输出 JSON 数组。
- 每个用例包含 `test_case_name`、`test_purpose`、`test_step`。
- `test_step` 是数组；每个元素只包含 `步骤描述` 和 `预期结果`。

### 通用生成规则
- 只输出严格 JSON 数组，不要输出解释、标题或代码块标记。
- 仅围绕当前 requirement 生成，不补充无关场景。
- `步骤描述`写人工操作，`预期结果`写可观察、可验证结果。
- `步骤描述`和`预期结果`都以中文句号结尾。
- JSON 必须使用双引号、无末尾逗号、可直接解析。

### 类型专属规则
- **按功能点划分用例**（2026-09-14 修订，取代"默认 1 个主用例"）：先通读需求的全部处理描述，识别需求明确描述的**独立功能点**（不同条件分支、不同处理功能、不同判定结果各是一个功能点）；**每个独立功能点一个用例**，用例数随功能点数自然增减，不设硬性上限。
- **同一功能点的多种情况聚合**：正常路径、需求明确描述的错误分支/异常判定（无效等价类）在同一用例内多步骤覆盖，不按 TR-ID 拆散。
- **总线收发类功能需求**（需求描述“通过一级CAN总线收到指令X → 发送/返回Y”形态，如轮询指令接收处理）按接口测试同款模式（2026-09-17 修订）：**每条指令 × 每条接收总线（CANA/CANB）＝ 一个独立用例**；用例内“全部正确 → 错误注入 → 全部正确”交替，覆盖需求及其引用条款描述的错误分支；预期写与步骤对应的软件可观察响应（遥测参数更新、计数绝对值），禁止罗列帧格式字段值清单。
- **协议格式表必须转化为覆盖清单**：总线接收类功能需求先识别数据包数和每包帧数，再覆盖表中全部适用字段；仲裁场/控制场分开测试，单帧轮询逐字段/逐字节覆盖，多帧按首帧/中间代表帧/尾帧覆盖字段与帧序号错误（2帧仅首+尾），每步只注入一个错误。
- **有序多包含双辅助数据包**：正确包按1至n完整推进并分摊单字段错误；前n-1包正确后各紧随一个同包错误，剩余错误在正确末包之前用末包逐项补测，最终以正确末包收尾；错误已测完则连续发剩余正确包。不得为覆盖字段重启正确序列，正确计数仅在正确包递增，错误计数仅按需求检查。
- **内存读出指令**：每条总线分为字段错误和地址边界两个用例；非4字节对齐地址直接按错误指令处理；每个地址区间覆盖下边界-1/下边界/下边界+1/中间对齐值/上边界-1/上边界/上边界+1，重合值去重。
- **内存数据轮询**：第1步在3.0s启动5s周期的正确内存读出指令，后续在5.0/10.0/15.0s…发送正确/单字段错误交替的内存数据轮询控制序列，不得用内存初始化代替前置指令。
- **不同功能点不得合并进同一个用例**：多个功能点测试目的不同，合并会使步骤失去主线——各自独立成一个用例。
- 只验证需求明确描述的功能点，不自动扩展边界、异常、无效、恢复、未收到或连续接收场景，除非输入信息明确要求。
- 预期结果必须覆盖需求、章节背景和输出流中明确给出的可观察输出，不要只写“软件正确处理”这类笼统结果。
- 若步骤最终需要使用关键字 Documentation 格式，最终步骤中不得保留未解析的占位符；尤其是 `${time}` 必须给出具体值。

### 输入信息
- 测试项名称：{tr_name}
- 测试需求：{tr_id}：{tr_handling}
- 充分性要求：{tr_sufficiency}
- 测试方法：{tr_testMethod}
- 通过准则：{tr_passCriteria}
```
