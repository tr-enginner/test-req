# 软件时序测试提示词模板

## 适用范围
- 模板 Key：`test-时序测试-STEP-GENERATED`
- 说明：适用于 software / software_variant + 时序测试。

## 业务说明
用于验证输入输出事件的先后关系、响应时间、周期、间隔和超时处理。时序参数以测试需求、接口协议和明确的环境约束为依据，不推测具体数值。

## 占位符
- `{title}`：测试需求项名称。
- `{requirementContext}`：测试需求项简介。
- `{inputFlowContext}`：输入流说明。
- `{processingContext}`：测试需求项具体涉及的处理逻辑。
- `{outputFlowContext}`：输出流说明。
- `{constraintContext}`：测试要求。

## 提示词正文
```prompt
### 任务目标
你要为一条时序测试需求项生成测试用例。

### 输出格式
- 只输出 JSON 数组。
- 每个用例包含 `test_case_name`、`test_purpose`、`covered_tr_items`、`test_step`。
- `test_case_name` 使用简洁的中文短语描述该用例的测试场景。
- `covered_tr_items` 是一个字符串数组，列出本用例覆盖的具体 TR 子需求项编号。
- `test_step` 是数组；每个元素必须包含 `步骤描述` 和 `预期结果`，可附加 `operation_type`、`channel`、`temporal`、`data_checks` 语义锚点。

### 通用生成规则
- 只输出严格 JSON 数组，不要输出解释、标题或代码块标记。
- 仅围绕当前测试需求生成，不补充无关场景。
- `步骤描述`写人工操作，`预期结果`写可观察、可验证结果，两者均以中文句号结尾。
- JSON 必须使用双引号、无末尾逗号、可直接解析。
- 协议输入说明数据包或帧的类型及正确性状态，不罗列协议字节值；操作所需时间参数应明确。

### 类型专属规则
- 从需求中提取事件、触发条件、顺序关系、时间基准、响应时限、发送周期、间隔和超时条件，按独立时序约束组织用例。
- 每个步骤明确触发事件和时刻或相对前一步的间隔；相对时间必须有明确参考事件，全部时间单位一致且可换算。
- 周期任务优先用前置步骤声明起点、周期、停止条件或执行次数；后续动作计算对应周期内的时间位置，不重复启动同一循环。
- 预期结果同时说明应发生或不应发生的输出事件及其允许时间窗口；需求给定上下限时，区分包含与不包含边界。
- 按需求覆盖正常顺序、允许时间范围及明确要求的超时、提前或延迟处理；边界测试的时间步长依据测量分辨率或需求，不凭空设置协议常量。
- 多帧或多包输入的时序验证必须保持需求规定的完整结构，并区分帧间隔、包间隔和完整接收后的处理时限。
- 除被验证的时序因素外，保持数据内容和前置状态有效，避免把格式错误或缺少前置条件误判为时序缺陷。
- 缺少时间基准、阈值或可观测条件时，明确指出缺少的证据，不编造数值或用“及时响应”等笼统描述代替断言。

### 输入信息
- 需求项名称：{title}
- 需求项简介：{requirementContext}
- 输入流说明：{inputFlowContext}
- 处理：{processingContext}
- 输出流说明：{outputFlowContext}
- 测试要求：{constraintContext}
```
