================================================================================
Matrix Embedded Agent — Code Review 支持条目列表
================================================================================

说明：Code Review 由 inspector agent 执行，专注于需要跨函数推理的语义缺陷和
需求-代码一致性验证。以下分类均不包含编码标准格式类规则（命名、注释格式等），
那些由静态分析工具（SpecChecker/cppcheck）处理。

--------------------------------------------------------------------------------
A. 运行时安全缺陷分析（Runtime Safety Defects）
--------------------------------------------------------------------------------

RS-01  数组/缓冲区越界（Array / Buffer Out-of-Bounds）
       · 数组索引来源追踪（外部输入、循环计数、计算值）
       · memcpy / memset / strncpy 大小参数验证
       · 调用点未强制缓冲区大小假设
       典型场景：接收帧长度字段直接用作数组下标，无上限检查

RS-02  数值溢出/下溢（Numeric Overflow / Underflow）
       · 8/16/32 位算术中间结果宽度不足（尤其是累加）
       · uint16×uint16 结果未扩宽至 uint32 即存储
       · 有符号/无符号混合导致回绕（wrap-around）
       典型场景：两个 uint16_t 相乘赋值给 uint16_t，溢出截断

RS-03  除零错误（Division by Zero）
       · 除数变量来源追踪（传感器读值、配置参数、时间差、计算值）
       · 除法/取模运算前是否有零值防护
       · 整除截断是否有意为之
       典型场景：用采样间隔做分母计算频率，间隔可能为 0

RS-04  中断非原子访问（Interrupt Non-Atomic Access）
       · 超过 CPU 原子宽度的变量（如 8 位 MCU 上的 uint32_t）
       · ISR 与主程序共享的全局/静态变量无临界区保护
       · 结构体多字段分步赋值被 ISR 抢占
       典型场景：主程序更新结构体两个字段间，ISR 读取到半更新状态

RS-05  缺少 volatile 限定（Missing volatile）
       · ISR 修改、主程序轮询的标志变量
       · 主程序写入、ISR 读取的控制变量
       · 编译器可能将变量优化到寄存器不从内存重新加载
       典型场景：主循环 while(!g_data_ready) 被编译器优化为死循环

RS-06  中断不安全读-修改-写（Interrupt-Unsafe RMW）
       · |=、&=、^= 等复合赋值在无中断保护时非原子
       · ISR 也对同一变量执行 RMW，导致更新丢失
       典型场景：主程序 event_flags |= NEW_EVENT 与 ISR event_flags |= ISR_EVENT 并发

RS-07  优先级反演（Priority Inversion）
       · 高优先级 ISR 依赖由低优先级 ISR 设置的共享状态
       · 低优先级 ISR 被打断时，高优先级 ISR 读到过时数据
       典型场景：高优先级定时器 ISR 使用低优先级 UART ISR 才能更新的配置值

RS-08  重入性风��（Reentrancy）
       · 函数使用 static 局部变量或全局变量保存中间状态
       · 同一函数从主程序和 ISR 两个上下文同时调用
       典型场景：UART 发送函数用 static 指针追踪缓冲位置，ISR 重入覆盖

RS-09  寄存器访问序列错误（Register Access Sequence）
       · 外设初始化顺序与 MCU 参考手册不符
       · 使能外设/DMA 前未完成地址/配置寄存器设置
       · 错误条件下进入未定义外设状态
       典型场景：先写 DMA_EN 再设置 DMA_SRC/DST 地址，导致首次传输地址无效

RS-10  看门狗未刷新路径���Watchdog Starvation）
       · 长运行循环（如传感器轮询、数据处理）内未喂狗
       · 错误处理分支（如重试循环）导致长时间不喂狗
       · 条件分支可能绕过喂狗语句
       典型场景：大数据块处理循环耗时超过看门狗超时，导致意外复位

RS-11  DMA 缓冲区所有权冲突（DMA Buffer Ownership Conflict）
       · DMA 传输未完成时 CPU 写入同一缓冲区
       · 无双缓冲或完成标志保护
       典型场景：DMA 搬运 ADC 原始数据期间，主程序覆写缓冲区内容

【新增】RS-21  不安全字符串操作（Unsafe String Operations）
       · strcpy / strcat / sprintf 写入固定缓冲，源字符串长度无上限
       · snprintf 第二参数为 sizeof(指针) 而非 sizeof(缓冲区)
       · strncpy / strncat 长度参数传入源串长度，无溢出保护
       · strtok 在 ISR 或多上下文中使用（隐含静态状态，不可重入）
       典型场景：sprintf(buf64, "[%lu] %s", ts, user_msg) 用户消息超 64 字节溢出

【新增】RS-13  资源泄漏（Resource Leak）
       · 外设独占锁（SPI 互斥量、CAN 邮箱）在错误路径未释放
       · 堆内存在处理失败分支未 free，导致堆耗尽
       · 所有退出路径（正常返回、错误返回）必须均有对应释放
       典型场景：获取 SPI 总线互斥量后读取失败直接 return，互斥量永久占用

【新增】RS-14  空指针解引用（Null Pointer Dereference）
       · 查找/分配函数返回值（可能为 NULL）未检查直接解引用
       · 可选输出参数（调用者可传 NULL）未防护直接写入
       · 跨函数传递指针：调用者不检查，被调函数直接解引用
       典型场景：lookup_device() 返回 NULL，init_device 直接访问 cfg->base_addr

【新增】RS-15  悬空指针与释放后使用（Dangling Pointer / Use-After-Free）
       · 返回局部变量地址（栈帧销毁后调用者��续使用）
       · free() 后继续读写已释放内存（Use-After-Free）
       · 局部结构体地址注册为回调参数，回调触发时结构体已销毁
       典型场景：函数返回局部数组指针，调用者写入已被覆盖的栈内存

【新增】RS-22  分配尺寸整数溢出（Allocation Size Integer Overflow）
       · malloc(a * b) 乘积在窄类型域溢出，导致欠分配后越界写入
       · 操作数来自外部输入时可被攻击者控制，漏洞可利用
       · 三重乘积（rows × cols × sizeof）任意一步溢出均致欠分配
       · calloc(n, size) 内置溢出检查，优于 malloc(n * size)
       典型场景：uint16_t count=1000 × elem_size=100 = 截断为 34464，
                 malloc 分配 34464 字节后写入 100000 字节，堆溢出

【新增】RS-17  浮点陷阱（Floating Point Traps）
       · NaN/Inf 传播：零向量归一化、除零产生 NaN，下游所有计算污染
       · 精确相等比较：float == float 几乎永远不成立，应使用容差比较
       · 累积误差：步进累加长期运行后位置/时间漂移，超出可接受范围
       典型场景：向量模长为 0 时除零产生 NaN，传播至 PID 控制输出

【新增】RS-23  双重释放（Double Free）
       · 同一指针在两条不同执行路径上均调用 free()，第二次 free 破坏堆分配器
       · 错误路径 free(p) 后落入函数末尾的 free(p)，未设置 p=NULL 分隔
       · 清理函数释放容器内部成员后，调用者再次释放同一容器指针
       · goto 错误标签含 free(p)，而部分错误路径在 goto 前已 free(p)
       典型场景：错误分支 free(buf) 后未 return，函数末尾再次 free(buf)，堆损坏

【新增】RS-24  错误码忽略后使用无效结果（Ignored Error Return）
       · 调用既返回错误码又通过指针输出结果的函数，返回值未检查即使用输出
       · SPI/I2C/UART 读取超时后输出参数含不确定值，调用者直接使用
       · Flash 读取 ECC 错误后数据为旧值或零，忽略错误码继续用于数组索引
       · 失败返回未写入输出参数，调用者使用的是上次成功调用的过期值
       典型场景：SPI_Read() 超时返回 -1，调用者未检查，��� rx_buf 内容写入控制寄存器

【新增】RS-25  非对齐内存访问（Misaligned Memory Access）
       · uint8_t* 强转 uint16_t*/uint32_t*/结构体指针，目标对齐要求未满足
       · 字节流按偏移量解析多字节字段：*(uint16_t*)(&buf[奇数偏移]) 触发 HardFault
       · 栈上 uint8_t 数组强转结构体指针，栈地址对齐无保证
       · DMA 目标缓冲区声明为 uint8_t[] 但后续按 uint32_t* 访问，对齐不足
       典型场景：Modbus 帧 &frame[1] 强转 uint16_t*，奇数地址在 Cortex-M0 触发 HardFault

【新增】RS-20  未初始化变量使用（Uninitialized Variable Use）
       · 局部变量只在部分分支赋值，其他分支直接使用（含随机栈数据）
       · 结构体部分字段初始化，未赋值字段被访问（非全局，无零初始化）
       · 输出参数（指针）在失败路径未写入，调用者使用原���垃圾值
       典型场景：parse_header 在校验失败路径返回未初始化的 result 结构体

--------------------------------------------------------------------------------
B. 需求-代码一致性验证（Requirement-Code Consistency, D1–D10）
--------------------------------------------------------------------------------

RC-D1  条件逻辑（Conditional Logic）
       · 所有触发条件是否完整实现（无遗漏条件）
       · 逻辑连接符 && / || 是否与需求一致（AND vs OR）
       · 条件嵌套/分组是否正确（括号优先级）
       · 是否存在意外逻辑反演（> 写成 <，== 写成 !=）
       典型场景：需求"AND 触发"实现为"OR 触发"

RC-D2  数值与常量（Values / Constants）
       · 数值阈值是否与需求完全一致（无魔数偏差）
       · 单位转换是否正确（ms vs s，°C vs °F，rpm vs rad/s）
       · 公式转录是否无误（系数、偏移量、量程）
       典型场景：需求参考电压 3.3 V，代码计算使用 5.0 V

RC-D3  运算符与边界（Operators / Boundaries）
       · 比较方向是否匹配（> vs >=，< vs <=）
       · 边界包含/排斥是否与需求一致
       · 饱和/钳位逻辑方向是否正确
       典型场景：需求"长度 > 64 时拒绝"，代码写成">= 64"

RC-D4  状态机（State Machines）
       · 所有需求定义的状态是否均已实现
       · 每条（源状态, 触发条件）→ 目标状态转移是否正确
       · 入口/出口动作是否按需求执行
       · 是否存在不可达状态或缺失转移（如缺少复位路径）
       典型场景：状态机缺少 ERROR→IDLE 的复位转移

RC-D5  时序与顺序（Timing / Sequencing）
       · 时间参数单位是否正确（节拍 vs 毫秒）
       · 操作执行顺序是否与需求强制顺序一致
       · 计时器/重置/去抖逻辑是否正确实现
       典型场景：上电后等待 100ms 再采样，代码实际等待 10ms（差 10 倍）

RC-D6  算术与公式（Arithmetic / Formulas）
       · 公式每一项是否逐一与需求匹配
       · 运算符优先级是否符合数学意图（加括号）
       · 中间结果数据类型宽度是否足够
       · 整除截断是否为设计意图
       典型场景：温度转换公式少减偏移量 0.5

RC-D7  错误处理（Error Handling）
       · 所有需求指定的错误/故障情况是否均有处理分支
       · 错误响应动作是否正确（丢包、计数、复位）
       · 未指定情况的默认行为是否安全（fail-safe）
       典型场景：需求要求 CRC 失败时丢包并计数，代码只丢包不计数

RC-D8  接口契约（Interface Contracts）
       · 参数类型、单位、范围是否与需求/ICD 一致
       · 返回值含义是否正确传达
       · 协议格式（字节序、字段位置、CRC 算法）是否匹配
       典型场景：SPI 帧长度字段需求为大端，代码发送小端

RC-D9  完整性（Completeness）
       · 需求所有子功能是否均已实现（无遗漏功能点）
       · 部分实现的功能是否有明确标记
       · 存根/TODO 是否替代了实际实现
       典型场景：需求描述三路传感器处理，代码只实现了两路

RC-D10 架构/硬件（Architecture / Hardware）
       · 寄存器地址和位域配置是否与 MCU 参考手册一致
       · 平台关键字（volatile、__attribute__、__io 等）使用是否正确
       · CPU 原子宽度假设是否与目标平台匹配
       · 端序处理是否符合平台字节序
       典型场景：定时器分频配置写入错误位域，导致实际频率偏差
